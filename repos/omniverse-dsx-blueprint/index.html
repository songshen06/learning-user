DSX Blueprint Usage Guide

How to use the NVIDIA Omniverse DSX Blueprint for AI Factory Digital Twins — from first install to daily operation. For end users, design engineers, and CFD engineers. No source code reading required.

Is this for me?

Hardware checklist

  • NVIDIA RTX Pro 6000 Blackwell GPU
  • Driver v570.169+
  • 64GB DDR5 RAM minimum
  • 1TB NVMe storage
  • Windows 10/11 or Ubuntu 22.04/24.04
  • Git + Git LFS
  • Node.js v20+ and npm 9+

Verify hardware: Run nvidia-smi. If you see an RTX Pro 6000 Blackwell with driver ≥570.169, you pass the first gate.

What you can do

  • Explore a photorealistic 3D digital twin of a 50-acre AI factory in your browser
  • Switch between GB200 and GB300 NVL72 GPU rack configurations
  • Run and visualize pre-baked CFD thermal simulations (temperature, pressure, hot aisle)
  • Run electrical loading simulations on different power configurations
  • Use AI chat to control the scene with natural language
  • Save and compare build configurations
  • View power and thermal KPIs in an analytics dashboard

What you cannot do

  • Deploy as a production app without customization — this is a developer blueprint
  • Run on macOS
  • Generate new CFD data (only visualize pre-baked data)
  • Use without the exact GPU specified
  • Use AI chat without an NVIDIA API key
  • Run the full scene without the separate DSX Content Pack download

If this isn't for you: For production deployment, customize this blueprint or use NVIDIA Cloud Functions (NVCF). For lower requirements, consider a lighter Omniverse Kit application.

What it does

The DSX Blueprint is a digital twin platform combining GPU-accelerated 3D rendering with an AI agent. It streams a complete 50-acre AI factory scene to web browsers via WebRTC, letting you configure hardware layouts, run simulations, and interact with the scene through an AI chat interface.

ComponentWhat users see
3D ViewerReal-time path-traced viewport in browser — no GPU needed on the client
ConfiguratorSwitches GPU types (GB200/GB300), rack variants, site layouts
CFD SimulationThermal heat maps (temperature, pressure) overlaid on the data hall
Electrical SimulationPower loading visualization with real-time metrics
AI AgentNatural-language chat controls the scene ("navigate to data hall 1")
AnalyticsKPI dashboard — power, thermal, GPU deployment stats
Camera ControlsPreset interior/exterior/CFD camera views

5-minute overview

The user journey from zero to exploring the digital twin:

  1. Check hardware — RTX Pro 6000, 64GB RAM, 1TB NVMe
  2. Install prerequisites — Git, Git LFS, Node.js, Docker (Linux), 7-Zip (Windows)
  3. Clone repo — git clone the blueprint + download DSX Content Pack from NGC (~several GB)
  4. Configure scene path — edit source/apps/dsx.kit to point auto_load_usd at extracted content
  5. Set API key (optional) — NVIDIA_API_KEY from build.nvidia.com for AI chat
  6. First run — Terminal 1: ./run_streaming.sh, Terminal 2: ./run_web.sh, open browser
  7. Explore — use toolbar to change configs, run simulations, chat with AI

First launch takes 5–8 minutes for shader compilation. Subsequent launches are fast.

Install

Set up DSX Blueprint from a fresh machine. Estimated time: 30–60 min (mostly content pack download).

Step 1: Hardware verification

nvidia-smi          # RTX Pro 6000 Blackwell, driver ≥570.169
free -h             # Linux — 64GB+
df -h               # 1TB+ free on NVMe

Step 2: Git + Git LFS

sudo apt-get install git git-lfs
git lfs install

Download from git-scm.com and git-lfs.com. Run installers.

Step 3: Node.js v20+

curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs
node --version   # Should be v20.x+
npm --version    # Should be 9.x+

Download from nodejs.org, run installer, ensure "Add to PATH" is checked. Restart terminal. Verify:

node --version
npm --version

Step 4: Docker (Linux only)

sudo apt-get install docker-ce docker-ce-cli containerd.io
sudo usermod -aG docker $USER
# Install NVIDIA Container Toolkit:
# https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html

Step 5: 7-Zip (Windows only)

Windows native zip archiver fails on deeply nested paths. Download from 7-zip.org.

Step 6: C++ toolchain + IDE

OSRequirements
WindowsVisual Studio 2019 with "Desktop development with C++" workload + Windows SDK
Linuxsudo apt-get install build-essential
BothVSCode: code.visualstudio.com

Step 7: Clone + download content

git clone https://github.com/NVIDIA-Omniverse-blueprints/omniverse-dsx-blueprint-for-ai-factories.git
cd omniverse-dsx-blueprint-for-ai-factories

Download the DSX Content Pack from NGC. Extract to:

/data/dsx/
C:\data\dsx\

Step 8: Configure scene path

Edit source/apps/dsx.kit:

[settings.app]
auto_load_usd = "C:\data\dsx\DSX_BP\Assembly\DSX_Main_BP.usda"   # Windows
auto_load_usd = "/data/dsx/DSX_BP/Assembly/DSX_Main_BP.usda"      # Linux

Step 9: NVIDIA API Key (optional — for AI chat)

Get a key from build.nvidia.com.

echo 'export NVIDIA_API_KEY="nvapi-..."' >> ~/.bashrc
source ~/.bashrc
[System.Environment]::SetEnvironmentVariable("NVIDIA_API_KEY", "nvapi-...", "User")
# Restart terminal

Skipping this step is fine — the 3D viewer, configurator, and simulations work without it.

Success check

node --version && npm --version && nvidia-smi

All three commands should succeed with correct versions.

Configure

The critical one-time setup step: linking the Kit application to your USD scene data.

Open source/apps/dsx.kit in any text editor. Find the [settings.app] section and set:

auto_load_usd = "<your_extract_path>/DSX_BP/Assembly/DSX_Main_BP.usda"

If you skip this, the application starts but no scene loads — you'll see a blank viewport.

Override at launch (no file editing needed):

./run_streaming.sh --/app/auto_load_usd=/custom/path/to/scene.usd

If NVIDIA_API_KEY is not set, the chat panel will display a message explaining how to enable the AI agent. Everything else still works.

First run & daily commands

You need two terminal windows — one for the Kit streaming server, one for the web frontend.

Terminal 1: Kit streaming server

cd omniverse-dsx-blueprint-for-ai-factories
./run_streaming.sh
cd omniverse-dsx-blueprint-for-ai-factories
.\run_streaming.bat

First run: builds everything (10–20 min) + shader compilation (5–8 min). Subsequent runs are fast.

Terminal 2: Web frontend

cd omniverse-dsx-blueprint-for-ai-factories
./run_web.sh
cd omniverse-dsx-blueprint-for-ai-factories
.\run_web.bat

First run: npm install downloads dependencies. Then Vite dev server starts on port 8081.

Browser

Pick the third URL shown in Terminal 2 (the streaming-related one):

http://localhost:8081?server=localhost

Docker alternative (Linux)

docker compose up -d
# Open: http://localhost:8080?server=localhost

What success looks like

  • Terminal 1 shows WebRTC signaling active on port 49100
  • Terminal 2 shows Vite dev server on port 8081
  • Browser displays the 3D AI factory scene
  • Left toolbar visible: Agent, Configurator, Analytics, Simulations, Camera
  • You can rotate/zoom/pan the viewport

Workflows

1. Launch the full stack

Every session starts here.

# Terminal 1
./run_streaming.sh

# Terminal 2
./run_web.sh

# Browser: streaming URL from Vite output

Docker (Linux):

docker compose up -d
# Open: http://localhost:8080?server=localhost
2. Change GPU / rack configuration
  1. Click Configurator icon in left toolbar
  2. Select GPU type: GB200 or GB300 NVL72
  3. Adjust site layout, power configuration
  4. Changes propagate instantly — viewport updates in real time

What changes: GPU deployment units (22 in hall_GPUs), DATAHALL layout, cooling infrastructure, power cabling.

3. Run CFD thermal simulation
  1. Click Simulations icon in left toolbar
  2. Select Thermal simulation
  3. Choose CFD timestep: 40, 60, 80, or 100
  4. Toggle temperature and/or pressure visualization

Pre-baked CGNS data overlays on the scene — hot aisle containment highlights heat patterns, temperature gradients color-map through the data hall.

CFD data is pre-baked. To generate new CFD for custom layouts, you need external CFD tools.

4. Run electrical loading simulation
  1. In SimulationPanel, select Electrical
  2. Adjust loading parameters (power draw per rack, redundancy)
  3. View power metrics — cables, panels, trays respond visually
  4. KPI metrics update in real time
5. Use AI chat to control the scene
  1. Click Agent icon (robot icon) in left toolbar
  2. Type natural-language commands:
"Navigate to data hall 1"
"Show me the hot aisle CFD"
"Switch to GB300 rack variant"
"Show the exterior camera view"
"What GPU models are currently deployed?"

The LangChain agent (llama-4-maverick) parses your message, routes it to scene handlers, and executes USD modifications automatically.

Requires NVIDIA_API_KEY from build.nvidia.com. Without it, the chat panel shows setup instructions.

Agent HTTP API (port 8012)

EndpointMethodPurpose
/api/agent/chatPOSTBlocking chat
/api/agent/chat/streamPOSTSSE streaming chat
/api/agent/resetPOSTClear conversation history
/api/agent/healthGETHealth check + API key validation
6. Switch cameras and views
  1. Click Camera icon in left toolbar
  2. Available presets:
CameraView
camera_int_datahall_01–04Interior data hall views
camera_ext_default_01–04Exterior / bird's-eye site views
cfd_cameraOptimized CFD visualization angle

Also controllable via AI chat: "Show me the exterior camera view"

7. View analytics and KPIs
  1. Click Analytics icon (chart icon) in left toolbar
  2. Dashboard shows:
  • Power consumption metrics across facility
  • Thermal KPIs from CFD data
  • GPU deployment statistics
  • Site-level utilization summaries

Charts update in real time as configurations and simulations change.

Troubleshooting

Launch & streaming

SymptomFix
Exits with code -11 (SIGSEGV)Use ./repo.sh launch dsx.kit instead. Or ensure RTX GPU + display available.
"WebGL2 support is required"Enable hardware acceleration in browser settings
Blank / no 3D sceneSet auto_load_usd in source/apps/dsx.kit to correct content pack path
Can't connect to streaming serverUse ?server=localhost&signalingPort=49100. Check env vars.
WebRTC connection failsEnsure ports 49100, 47995–48012, 49000–49007 open in firewall
Hangs during render initDisable IOMMU at system level (BIOS/UEFI)

Build

SymptomFix
Build fails on fresh checkoutUse ./repo.sh build (handles everything automatically)
Build fails after code changesVerify same .kit files in repo.toml, premake5.lua, source/apps/
Stale dependenciesClean build: ./repo.sh build -c or clear cache: ./repo.sh launch -- --clear-cache --clear-data --reset-user
Windows path too longMove repo closer to drive root (e.g., C:\dsx\)
exFAT drive errorsMove repo to NTFS-formatted drive
Docker disk space exhausteddocker container prune (safe) or docker system prune (⚠ aggressive)

Performance

SymptomFix
First launch very slow (5–8 min)Normal — RTX shader compilation. Wait. Subsequent launches fast.
Low FPS / choppyReduce: ?width=1280&height=720&fps=30. Check GPU with nvidia-smi.

AI agent

SymptomFix

Glossary

TermDefinition
KitNVIDIA Omniverse Kit SDK — the GPU-accelerated application framework for building 3D tools
USD / OpenUSDUniversal Scene Description — Pixar's open standard for 3D scene composition and interchange
WebRTCWeb Real-Time Communication — browser-based protocol for streaming video, audio, and data between peers
NVCFNVIDIA Cloud Functions — serverless GPU container hosting for Kit applications
NVL72NVIDIA's rack-scale GPU design — 72 GPUs interconnected in a single rack
GB200 / GB300GPU product generations used in DSX rack configurations
CFDComputational Fluid Dynamics — simulation of fluid/air flow and heat transfer
CGNSCFD General Notation System — file format for CFD simulation data
SimReadyNVIDIA's standard for USD assets that include both geometry and metadata for simulation
Content PackThe multi-GB USD scene dataset downloaded separately from NGC — contains the AI factory 3D model
NGCNVIDIA GPU Cloud — catalog for datasets, containers, and models
SignalingThe WebRTC process of negotiating a peer-to-peer connection between browser and streaming server
Kit ExtensionA modular component in the Kit SDK — every feature (rendering, streaming, CAE) is an extension
CAEComputer-Aided Engineering — simulation extensions for CFD, thermal, and structural analysis
SSEServer-Sent Events — HTTP streaming protocol used by the AI agent for real-time chat responses
LangChainLLM orchestration framework used by the AI agent to route chat messages to scene handlers

Tutorial

Step-by-step walkthrough built from each task's Trace task, in journey order.

  1. Hardware check: Run nvidia-smi. Confirm RTX Pro 6000 Blackwell and driver ≥570.169.
  2. Prerequisites check: Run node --version && npm --version && nvidia-smi. All three should succeed.
  3. First launch: Open two terminals. Run ./run_streaming.sh in one, ./run_web.sh in the other. Open the third URL from Vite output. Verify the 3D scene renders and camera responds to interaction.
  4. GPU configuration: Click the Configurator icon. Switch from GB200 to GB300. Verify rack units change in the viewport.
  5. AI chat control: Open the Agent panel. Type "navigate to data hall 1." Confirm camera moves to an interior data hall view.
  6. Troubleshooting practice: Deliberately launch with wrong auto_load_usd. Observe blank scene. Correct the path and relaunch.

Exercises

Self-checks framed from each task's Practice task.

  1. Suitability: List your project requirements. Map them against "What you can do." Identify at least 3 gaps where you'll need to extend the blueprint.
  2. Setup speed: Time a full setup from scratch on a clean VM. Target: under 1 hour. Identify the slowest step and document how to parallelize it.
  3. Remote streaming: Start the streaming server. Connect from a different machine on the same network using ?server=IP. Verify remote streaming works.
  4. Full workflow demo: Start GB200 → run thermal CFD at timestep 60 → switch to GB300 → run electrical loading → use AI chat to query "what is the current GPU configuration?" → screenshot the analytics dashboard. Time the full sequence.
  5. Build failure recovery: Rename a .kit file in source/apps/ without updating repo.toml or premake5.lua. Try to build. Observe the error. Fix all three locations and rebuild.
