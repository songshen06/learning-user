DSX Blueprint 使用指南

如何使用 NVIDIA Omniverse DSX Blueprint 构建 AI 工厂数字孪生 —— 从首次安装到日常操作。面向最终用户、设计工程师和 CFD 工程师。无需阅读源代码。

适合我吗？

谁应该使用 DSX Blueprint

角色是否适合你能做什么
设计工程师 / 最终用户是通过 Web UI 浏览、配置和运行仿真
CFD 工程师是可视化预生成的 CFD 数据；新 CFD 需外部工具生成
设计工程师 / 美术师是使用 SimReady USD 资产，修改 3D 场景
应用开发者是扩展 Kit 应用（C++/Python）或 Web 前端（React）
AI 工程师是配置/扩展 AI 对话代理
非技术业务用户否非开箱即用产品；需要技术配置
macOS 用户否仅支持 Windows 10/11 或 Ubuntu 22.04/24.04

硬件检查清单

  • NVIDIA RTX Pro 6000 Blackwell GPU
  • 驱动程序 ≥ v570.169
  • 最小 64GB DDR5 内存
  • 1TB NVMe 存储
  • Windows 10/11 或 Ubuntu 22.04/24.04
  • Git + Git LFS
  • Node.js v20+ 和 npm 9+

验证硬件：运行 nvidia-smi。如果看到 RTX Pro 6000 Blackwell 且驱动 ≥570.169，则通过第一关。

你能做什么

  • 在浏览器中浏览完整的 50 英亩 AI 工厂照片级 3D 数字孪生
  • 在 GB200 和 GB300 NVL72 GPU 机架配置之间切换
  • 运行并可视化预生成的 CFD 热力仿真（温度、压力、热通道）
  • 在不同电力配置上运行电力负载仿真
  • 通过 AI 对话用自然语言控制场景
  • 保存和对比多种构建配置方案
  • 在分析仪表盘中查看电力和热力 KPI

你不能做什么

  • 未经定制直接部署为生产应用 — 这是一个开发者蓝图
  • 在 macOS 上运行
  • 生成新的 CFD 数据（仅能可视化预生成数据）
  • 在非指定 GPU 上运行
  • 在没有 NVIDIA API 密钥的情况下使用 AI 对话
  • 不下载独立的 DSX Content Pack 就运行完整场景

如果这不适合你：用于生产部署请定制此蓝图或使用 NVIDIA Cloud Functions (NVCF)。如需更低硬件要求，请考虑更轻量的 Omniverse Kit 应用。

功能概览

DSX Blueprint 是一个将 GPU 加速 3D 渲染与 AI 代理相结合的数字孪生平台。它通过 WebRTC 将完整的 50 英亩 AI 工厂场景实时流式传输到 Web 浏览器，让你可以配置硬件布局、运行仿真，并通过 AI 对话界面与场景交互。

组件用户所见
3D 查看器浏览器中实时光线追踪视口 — 客户端无需 GPU
配置器切换 GPU 类型（GB200/GB300）、机架变体、场地布局
CFD 仿真数据大厅上的热力图叠加（温度、压力）
电力仿真带实时指标的电力和负载可视化
AI 代理自然语言对话控制场景（"导航到数据大厅 1"）
分析面板KPI 仪表盘 — 电力、热力、GPU 部署统计
摄像机控制预设的室内/室外/CFD 摄像机视角

5 分钟速览

从零到探索数字孪生的用户旅程：

  1. 检查硬件 — RTX Pro 6000、64GB 内存、1TB NVMe
  2. 安装前提软件 — Git、Git LFS、Node.js、Docker（Linux）、7-Zip（Windows）
  3. 克隆仓库 — git clone 蓝图 + 从 NGC 下载 DSX Content Pack（数 GB）
  4. 配置场景路径 — 编辑 source/apps/dsx.kit，将 auto_load_usd 指向解压后的内容
  5. 设置 API 密钥（可选） — 从 build.nvidia.com 获取 NVIDIA_API_KEY 启用 AI 对话
  6. 首次运行 — 终端1：./run_streaming.sh，终端2：./run_web.sh，打开浏览器
  7. 探索 — 使用工具栏切换配置、运行仿真、与 AI 对话

首次启动需要 5–8 分钟进行着色器编译。后续启动很快。

安装

从全新机器安装 DSX Blueprint。预计耗时：30–60 分钟（主要是内容包下载）。

步骤 1：硬件验证

nvidia-smi          # RTX Pro 6000 Blackwell，驱动 ≥570.169
free -h             # Linux — 64GB+
df -h               # NVMe 上 1TB+ 可用空间

步骤 2：Git + Git LFS

sudo apt-get install git git-lfs
git lfs install

从 git-scm.com 和 git-lfs.com 下载安装程序运行。

步骤 3：Node.js v20+

curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs
node --version   # 应为 v20.x+
npm --version    # 应为 9.x+

从 nodejs.org 下载安装程序，确保勾选"Add to PATH"。重启终端后验证：

node --version
npm --version

步骤 4：Docker（仅 Linux）

sudo apt-get install docker-ce docker-ce-cli containerd.io
sudo usermod -aG docker $USER
# 安装 NVIDIA Container Toolkit：
# https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html

步骤 5：7-Zip（仅 Windows）

Windows 自带 zip 压缩工具在处理深层嵌套路径时会失败。从 7-zip.org 下载。

步骤 6：C++ 工具链 + IDE

操作系统要求
WindowsVisual Studio 2019，需选择"桌面 C++ 开发"工作负载 + Windows SDK
Linuxsudo apt-get install build-essential
通用VSCode：code.visualstudio.com

步骤 7：克隆仓库 + 下载内容

git clone https://github.com/NVIDIA-Omniverse-blueprints/omniverse-dsx-blueprint-for-ai-factories.git
cd omniverse-dsx-blueprint-for-ai-factories

从 NGC 下载 DSX Content Pack。解压到：

/data/dsx/
C:\data\dsx\

步骤 8：配置场景路径

编辑 source/apps/dsx.kit：

[settings.app]
auto_load_usd = "C:\data\dsx\DSX_BP\Assembly\DSX_Main_BP.usda"   # Windows
auto_load_usd = "/data/dsx/DSX_BP/Assembly/DSX_Main_BP.usda"      # Linux

步骤 9：NVIDIA API 密钥（可选 — 用于 AI 对话）

从 build.nvidia.com 获取密钥。

echo 'export NVIDIA_API_KEY="nvapi-..."' >> ~/.bashrc
source ~/.bashrc
[System.Environment]::SetEnvironmentVariable("NVIDIA_API_KEY", "nvapi-...", "User")
# 重启终端

跳过此步骤也没问题 — 3D 查看器、配置器和仿真功能无需密钥即可正常使用。

安装成功验证

node --version && npm --version && nvidia-smi

三条命令均应成功并显示正确的版本。

配置

关键的一次性设置步骤：将 Kit 应用关联到你的 USD 场景数据。

用任意文本编辑器打开 source/apps/dsx.kit。找到 [settings.app] 部分并设置：

auto_load_usd = "<你的解压路径>/DSX_BP/Assembly/DSX_Main_BP.usda"

如果跳过此步骤，应用会启动但不会加载场景 — 你将看到空白视口。

启动时覆盖（无需编辑文件）：

./run_streaming.sh --/app/auto_load_usd=/自定义/路径/场景.usd

流式连接设置

流式连接可通过 URL 查询参数或环境变量配置：

参数环境变量默认值说明
serverVITE_OMNIVERSE_SERVERlocalhostKit 服务器地址
signalingPortVITE_SIGNALING_PORT49100信令端口
width—1920流宽度
height—1080流高度
fps—60目标帧率

示例：http://localhost:8080?server=192.168.1.100&width=1280&height=720

如果未设置 NVIDIA_API_KEY，对话面板会显示启用 AI 代理的说明。其他功能不受影响。

首次运行与日常命令

需要两个终端窗口 — 一个用于 Kit 流式服务器，一个用于 Web 前端。

终端 1：Kit 流式服务器

cd omniverse-dsx-blueprint-for-ai-factories
./run_streaming.sh
cd omniverse-dsx-blueprint-for-ai-factories
.\run_streaming.bat

首次运行：构建所有内容（10–20 分钟）+ 着色器编译（5–8 分钟）。后续运行很快。

终端 2：Web 前端

cd omniverse-dsx-blueprint-for-ai-factories
./run_web.sh
cd omniverse-dsx-blueprint-for-ai-factories
.\run_web.bat

首次运行：npm install 下载依赖。然后 Vite 开发服务器在端口 8081 启动。

浏览器

选择终端 2 中显示的第三个 URL（流式相关的那个）：

http://localhost:8081?server=localhost

Docker 替代方案（Linux）

docker compose up -d
# 打开：http://localhost:8080?server=localhost

成功的标志

  • 终端 1 显示 WebRTC 信令在端口 49100 活跃
  • 终端 2 显示 Vite 开发服务器在端口 8081 运行
  • 浏览器显示 3D AI 工厂场景
  • 左侧工具栏可见：Agent、Configurator、Analytics、Simulations、Camera
  • 可以旋转/缩放/平移视口

工作流

1. 启动完整套件

每次会话的起点。

# 终端 1
./run_streaming.sh

# 终端 2
./run_web.sh

# 浏览器：Vite 输出的流式 URL

Docker（Linux）：

docker compose up -d
# 打开：http://localhost:8080?server=localhost
2. 切换 GPU / 机架配置
  1. 点击左侧工具栏 Configurator 图标
  2. 选择 GPU 类型：GB200 或 GB300 NVL72
  3. 调整场地布局、电力配置
  4. 更改即时生效 — 视口实时更新

场景变化：GPU 部署单元（hall_GPUs 中 22 个）、DATAHALL 布局、冷却基础设施、电力布线。

3. 运行 CFD 热力仿真
  1. 点击左侧工具栏 Simulations 图标
  2. 选择 Thermal（热力）仿真
  3. 选择 CFD 时间步：40、60、80 或 100
  4. 切换温度和/或压力可视化

预生成的 CGNS 数据叠加在场景上 — 热通道封存高亮显示热力模式，温度梯度通过数据大厅进行颜色映射。

CFD 数据是预生成的。如需为自定义布局生成新的 CFD 数据，需要使用外部 CFD 工具。

4. 运行电力负载仿真
  1. 在 SimulationPanel 中，选择 Electrical（电力）
  2. 调整负载参数（单机架功耗、冗余设置）
  3. 查看电力指标 — 电缆、面板、走线架视觉上同步响应
  4. KPI 指标实时更新
5. 使用 AI 对话控制场景
  1. 点击左侧工具栏 Agent 图标（机器人图标）
  2. 输入自然语言命令：
"导航到数据大厅 1"
"显示热通道 CFD"
"切换到 GB300 机架变体"
"显示外部摄像机视角"
"当前部署了哪些 GPU 型号？"

LangChain 代理（llama-4-maverick）解析你的消息，路由到场景处理器，并自动执行 USD 修改。

需要从 build.nvidia.com 获取 NVIDIA_API_KEY。没有密钥时，对话面板会显示设置说明。

Agent HTTP API（端口 8012）

端点方法用途
/api/agent/chatPOST阻塞式对话
/api/agent/chat/streamPOSTSSE 流式对话
/api/agent/resetPOST清除对话历史
/api/agent/healthGET健康检查 + API 密钥验证
6. 切换摄像机视角
  1. 点击左侧工具栏 Camera 图标
  2. 可用预设视角：
摄像机视角
camera_int_datahall_01–04数据大厅内部视图
camera_ext_default_01–04外部 / 鸟瞰视图
cfd_camera优化的 CFD 可视化角度

也可通过 AI 对话控制："显示外部摄像机视角"

7. 查看分析面板与 KPI
  1. 点击左侧工具栏 Analytics 图标（图表图标）
  2. 仪表盘显示：
  • 全设施电力消耗指标
  • 来自 CFD 数据的热力 KPI
  • GPU 部署统计
  • 场地级利用率汇总

图表随配置和仿真变化实时更新。

故障排除

启动与流式传输

症状解决方法
以代码 -11（SIGSEGV）退出改用 ./repo.sh launch dsx.kit。或确保 RTX GPU + 显示器可用。
"需要 WebGL2 支持"在浏览器设置中启用硬件加速
空白 / 无 3D 场景在 source/apps/dsx.kit 中将 auto_load_usd 设置为正确的内容包路径
无法连接到流式服务器使用 ?server=localhost&signalingPort=49100。检查环境变量。
WebRTC 连接失败确保防火墙开放端口 49100、47995–48012、49000–49007
渲染初始化时卡住在系统层面禁用 IOMMU（BIOS/UEFI）

构建

症状解决方法
全新克隆后构建失败使用 ./repo.sh build（自动处理所有步骤）
代码改动后构建失败验证 repo.toml、premake5.lua、source/apps/ 中列出的 .kit 文件一致
过期依赖清洁构建：./repo.sh build -c 或清缓存：./repo.sh launch -- --clear-cache --clear-data --reset-user
Windows 路径过长将仓库移至靠近驱动器根目录的位置（如 C:\dsx\）
exFAT 驱动器错误将仓库移至 NTFS 格式的驱动器
Docker 磁盘空间耗尽docker container prune（安全）或 docker system prune（⚠ 激进清理）

性能

症状解决方法
首次启动非常慢（5–8 分钟）正常现象 — RTX 着色器编译。等待。后续启动快速。
帧率低/卡顿降低：?width=1280&height=720&fps=30。用 nvidia-smi 检查 GPU。
场景不完整运行 git lfs pull 下载大型二进制资产

AI 代理

症状解决方法
"API 密钥未配置"从 build.nvidia.com 获取密钥，设置 NVIDIA_API_KEY 环境变量
代理返回错误在 build.nvidia.com 验证密钥。健康检查：curl http://localhost:8012/api/agent/health
代理无响应检查 DSX_AGENT_PORT（默认 8012）是否与前端 VITE_DSX_AGENT_PORT 匹配
回答不正确重置对话：curl -X POST http://localhost:8012/api/agent/reset

应用级（安全，每次启动时）：

# Linux
rm -rf ~/.local/share/ov ~/.cache/packman ~/.cache/uv
# Windows — 删除：
# %LOCALAPPDATA%\ov  %PM_PACKAGES_ROOT%  %LOCALAPPDATA%\uv\cache

术语表

术语定义
KitNVIDIA Omniverse Kit SDK — GPU 加速的应用框架，用于构建 3D 工具
USD / OpenUSD通用场景描述（Universal Scene Description）— Pixar 的开放标准，用于 3D 场景组合与交换
WebRTCWeb 实时通信 — 基于浏览器的点对点视频、音频和数据流传输协议
NVCFNVIDIA Cloud Functions — 无服务器 GPU 容器托管，用于 Kit 应用
NVL72NVIDIA 机架级 GPU 设计 — 单个机架内 72 个 GPU 互联
GB200 / GB300DSX 机架配置中使用的 GPU 产品代际
CFD计算流体力学（Computational Fluid Dynamics）— 流体/气流和热传递仿真
CGNSCFD 通用符号系统 — CFD 仿真数据的文件格式
SimReadyNVIDIA USD 资产标准，同时包含几何体数据和仿真元数据
Content Pack从 NGC 单独下载的多 GB USD 场景数据集 — 包含 AI 工厂 3D 模型
NGCNVIDIA GPU Cloud — 数据集、容器和模型目录
信令（Signaling）WebRTC 中协商浏览器与流式服务器间点对点连接的过程
Kit 扩展Kit SDK 中的模块化组件 — 每个功能（渲染、流式传输、CAE）都是一个扩展
CAE计算机辅助工程 — 用于 CFD、热力和结构分析的仿真扩展
SSE服务器推送事件 — AI 代理用于实时对话响应的 HTTP 流式协议
LangChainLLM 编排框架，AI 代理用它将会话消息路由到场景处理器

按旅程顺序、基于每个任务跟踪练习构建的分步演练。

  2. 前提检查：运行 node --version && npm --version && nvidia-smi。三条命令均应成功。
  3. 首次启动：打开两个终端。一个运行 ./run_streaming.sh，另一个运行 ./run_web.sh。在浏览器中打开 Vite 输出的第三个 URL。确认 3D 场景渲染正常且摄像机响应交互。
  4. GPU 配置：点击 Configurator 图标。从 GB200 切换到 GB300。确认视口中机架单元发生变化。
  5. AI 对话控制：打开 Agent 面板。输入 "导航到数据大厅 1"。确认摄像机移动到数据大厅内部视图。
  6. 故障排除练习：故意使用错误的 auto_load_usd 启动。观察空白场景。修正路径后重新启动。

练习

基于每个任务实践练习的自检题目。

  1. 适用性评估：列出你的项目需求。对照"你能做什么"进行匹配。找出至少 3 处你需要扩展蓝图的地方。
  2. 安装速度：在干净的虚拟机上计时完整安装。目标：1 小时内完成。找出最慢的步骤并记录如何并行化。
  3. 远程流式传输：启动流式服务器。从同一网络的另一台机器使用 ?server=IP 连接。验证远程流式传输正常工作。
  4. 完整工作流演示：从 GB200 开始 → 在时间步 60 运行热力 CFD → 切换到 GB300 → 运行电力负载仿真 → 用 AI 对话查询"当前 GPU 配置是什么？" → 截屏分析仪表盘。计时整个流程。
  5. 构建故障恢复：重命名 source/apps/ 中的一个 .kit 文件但不更新 repo.toml 或 premake5.lua。尝试构建。观察错误。修正三处后重新构建。
