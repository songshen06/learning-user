NemoClaw

AI 代理的 OpenShell 沙箱管理器 · TypeScript / oclif / Node.js ≥22.16 · v0.1.0 (Alpha)

这个仓库做什么

NemoClaw 在 openshell CLI 之上封装了一层高级编排：引导式入门向导、沙箱生命周期（创建/连接/执行/恢复/重建/销毁）、推理提供商路由、网络策略管理、配置锁定（shields）和消息平台集成。通过单一 CLI 提供引导式入门、加固蓝图、路由推理、网络策略和生命周期管理。

关键设计约定

  • 薄命令，厚库：src/commands/ 类只解析参数和验证；所有逻辑在 src/lib/
  • Flexible taxonomy：oclif 接受 nemoclaw <name> <command> 格式，无需 : 分隔符
  • Agent-aware：OpenClaw vs Hermes 差异在运行时通过变体检查处理
  • 声明式蓝图：镜像 digest、版本范围和推理 profile 固定在 YAML 中
  • 同目录测试：.test.ts 文件与源码同目录放在 src/lib/
  • 凭证不落盘：API key 注册到 OpenShell 网关，仅内存存储

§10 个模块详解

STEP 1

心智模型

NemoClaw 是用户 CLI 和 OpenShell 之间的"薄编排层"。3 个代理变体：OpenClaw（聊天）、Hermes（API）、dcode（无头编码）。理解技术栈后再看代码。

关键：README.md:12-13 + blueprint.yaml + src/nemoclaw.ts（16 行）+ quickstart-langchain-deepagents-code.mdx
起点：README 第 12 行 — "reference stack for running always-on AI agents inside OpenShell sandboxes"。
STEP 2

CLI 架构

oclif pattern strategy + flexible taxonomy。public-dispatch.ts 路由 <name> <command> 格式。runner.ts 注入生命周期 hooks。6 步分发链：shim → dispatchCli → taxonomy → oclif → runner → command.run()。

关键：src/nemoclaw.ts + src/lib/cli/public-dispatch.ts + src/lib/runner.ts
起点：src/nemoclaw.ts — 16 行。然后追踪 public-dispatch.ts 中的 6 步分发序列。
STEP 3

蓝图系统

声明式 YAML 定义沙箱镜像、OpenShell 版本范围、5 个推理 profile、资源配额。Dockerfile 注入 NEMOCLAW_* 构建参数，含 secret 安全排除。

关键：nemoclaw-blueprint/blueprint.yaml + provider-profiles/ + policies/ + Dockerfile
起点：blueprint.yaml — 108 行。找 digest pin + 5 个推理 profile。然后看 Dockerfile 的构建参数注入。
STEP 4

入门流程

最复杂的编排逻辑。8 步向导：preflight → gateway → provider → credential → build → policy → messaging → finalize。每步可保存/恢复。

关键：src/lib/onboard.ts + src/lib/onboard/ + src/lib/state/
起点：src/lib/onboard.ts — 找到串联 8 个阶段的主编排器。
STEP 5

状态与恢复

入门 session 持久化 + 运行时崩溃恢复。--resume 重放保存的参数；recover 幂等重启网关。doctor 运行完整诊断。

关键：src/lib/state/ + runtime-recovery.ts + registry-recovery-action.ts
起点：src/lib/state/ — session 如何序列化为 JSON。然后 nemoclaw <name> doctor 运行完整诊断。
STEP 6

沙箱生命周期

容器管理：connect（SSH 代理）、exec、rebuild（备份→删除→创建→恢复）、recover。全部通过 OpenShell API。

关键：src/lib/sandbox/ + src/commands/sandbox/ + sandbox-base-image.ts
起点：src/commands/sandbox/connect.ts — 追踪 readiness probe → gateway 恢复 → SSH attach。
STEP 7

推理路由

将 NEMOCLAW_PROVIDER 映射到 OpenShell 网关路由。11+ 提供商。凭证仅内存注册，不落盘。

关键：src/lib/inference/ + blueprint.yaml 推理段 + hermes-provider-auth.ts
起点：blueprint.yaml components.inference.profiles — 5 个声明式 profile。
STEP 8

网络策略

3 个层级（Restricted/Balanced/Open）+ 自定义预设。Agent-aware 过滤（Hermes 排除 Brave Search）。

关键：src/lib/policy/ + nemoclaw-blueprint/policies/ + private-networks.yaml
起点：src/lib/policy/ — 找到层级 → 预设映射表。
STEP 9

安全与 Shields

配置锁定（shields up/down）、凭证安全、沙箱加固、Hermes secret 边界校验器。

关键：src/lib/shields/ + src/lib/security/ + src/lib/credentials/
起点：src/lib/shields/ — shields up 的可变性矩阵。
STEP 10

集成点

消息（Slack/Discord/Telegram）、仪表盘 UI、SSH 隧道。令牌在构建时烘焙到沙箱镜像中。

关键：src/lib/messaging/ + dashboard/ + tunnel/ + hermes-dashboard.ts
起点：src/lib/messaging/ — Slack 双令牌如何处理。
BONUS

Agent Skills 与领域类型

25 个 checked-in SKILL.md 文件 + 共享领域类型（phases, presets, variants）。Skills 教 AI 编码助手使用本仓库。

关键：.agents/skills/ + skills/nemoclaw-user-guide/ + src/lib/domain/
起点：.agents/skills/ — 浏览 25 个 skill。然后 src/lib/domain/ 看核心类型。

§教程 · 跟读任务

1. 画出技术栈图

读 README.md 第 1-20 行。不看代码，画出：用户 → NemoClaw CLI → OpenShell → Docker → Agent → Provider。在每个箭头上标注跨过的数据。

2. 追踪 CLI 分发链

读 src/nemoclaw.ts（16 行）→ src/lib/cli/public-dispatch.ts → src/commands/onboard.ts。追踪 nemoclaw onboard --fresh 从命令行到 src/lib/onboard.ts 的完整路径。写 5 行笔记：每一步在哪个文件、做了什么。

3. 理解蓝图 digest pin

读 nemoclaw-blueprint/blueprint.yaml 全文。找到 digest 字段和 components.sandbox.image 中的 digest。验证它们一致。理解为什么两个地方都要 pin（供应链安全，issue #1438）。

4. 追踪入门 8 步状态机

读 src/lib/onboard.ts。找到 8 个阶段。画状态机：哪些步骤可以 resume，哪些在 --resume 时必须重跑。找到每步保存 session state 的位置。

5. 追踪 recover 幂等性

读 src/lib/runtime-recovery.ts。找到 recover 如何判断"网关已健康"（幂等退出）vs"需要重启"。对比 connect 中的自动恢复路径。

6. 追踪凭证流（不落盘保证）

读 src/lib/inference/ + src/lib/credentials/。追踪 NEMOCLAW_PROVIDER=openai 如何将 API key 传递到沙箱而不写入主机磁盘。验证仅网关存储的声明。

7. 追踪 agent-aware 策略过滤

读 src/lib/policy/。找到 Hermes 预设（nous-web、nous-image）在哪里添加，OpenClaw 专属预设（brave）在哪里为 Hermes 排除。画过滤管道。

8. 追踪 shields up/down 生命周期

读 src/lib/shields/。找到 shields up 在哪里读取已保存的限制性策略。追踪 shields down --timeout 5m → timeout 如何触发自动重新锁定。

9. 追踪消息令牌烘焙

读 src/lib/messaging/。找到 Slack SLACK_APP_TOKEN 在哪里存储到独立的 slack-app OpenShell provider（不与 bot token 混在一起）。理解为什么 Socket Mode 需要两个 token。

10. 阅读 nemoclaw-user-guide skill

读 skills/nemoclaw-user-guide/SKILL.md。找到 MCP server URL 和检索顺序（MCP → llms.txt → .md 页面）。理解这个 skill 如何教 AI 助手获取实时文档。

§练习 · 实战检查

练习 1 · 对比 Docker 直跑 vs NemoClaw

模块：心智模型  难度：★☆☆  预计：30 min

列出 NemoClaw 相比直接在 Docker 中运行代理提供的 5 个额外价值（提示：onboarding、policy、routing、shields、recovery）。对每个，指出哪个 src/lib/ 模块实现了它。

练习 2 · 添加自定义 CLI 命令

模块：CLI 架构  难度：★★☆  预计：1h

创建 src/commands/dev-info.ts（最小 oclif command class）。npm run build:cli 后运行 nemoclaw dev-info。验证自动发现。然后添加 --json flag。

练习 3 · 添加 resource profile

模块：蓝图系统  难度：★★☆  预计：30 min

在 blueprint.yaml 中添加 ai-researcher profile（cpu: 80%, memory: 80%）。运行 npm run validate:configs。验证 schema 通过。

练习 4 · 入门计时分析

模块：入门流程  难度：★★☆  预计：1h + Docker

设置 NEMOCLAW_TRACE=1，运行 nemoclaw onboard --fresh。记录每步时间戳。识别最慢的步骤（通常是 sandbox build / image push）。记录优化机会。

练习 5 · 崩溃恢复演练

模块：状态与恢复  难度：★☆☆  预计：20 min

杀掉 OpenShell gateway 进程。运行 nemoclaw <name> recover。观察：检测 → 重启 → 验证。再次运行 recover 验证幂等性。

练习 6 · 对比 exec vs docker exec

模块：沙箱生命周期  难度：★☆☆  预计：15 min

运行 nemoclaw <name> exec -- echo $HOME（应输出 /sandbox）。然后运行 docker exec <container> echo $HOME（输出 /root）。记录为什么 NemoClaw exec 对 agent 配置解析更安全。

练习 7 · 运行时切换推理提供商

模块：推理路由  难度：★★☆  预计：30 min

用 NVIDIA cloud onboard。然后运行 nemoclaw inference set --provider ollama --model llama3。追踪网关路由如何变化。验证 status 反映新的提供商。

练习 8 · 添加和移除策略预设

模块：网络策略  难度：★★☆  预计：30 min

用 Restricted 层级 onboard。用 policy-add 添加一个预设。验证 agent 现在可以访问之前被阻止的服务。然后移除它，验证访问被再次阻止。

练习 9 · Shields 生命周期测试

模块：安全与 Shields  难度：★☆☆  预计：15 min

运行 shields up，然后 config get（验证已锁定）。运行 shields down --timeout 1m。等 1 分钟。运行 shields status 验证自动重新锁定。

练习 10 · 写一个 dev-guide skill

模块：Agent Skills  难度：★★☆  预计：1h

仿照 nemoclaw-user-guide/SKILL.md 格式，写 nemoclaw-dev-guide SKILL.md（30-50 行）：frontmatter / When to Use / First Command。放在 .agents/skills/。分析：什么开发者请求会触发它？

§术语表

术语定义
OpenShellNVIDIA 的沙箱管理系统 — 处理容器生命周期、路由和 SSH 隧道
Blueprint（蓝图）声明式 YAML，定义沙箱镜像、版本范围、推理 profile（nemoclaw-blueprint/blueprint.yaml）
Onboard（入门）8 步交互式设置向导（nemoclaw onboard）
Sandbox（沙箱）运行 AI 代理的隔离 Docker 容器，具有网络控制
Gateway（网关）管理沙箱路由和推理的 OpenShell 进程
Flexible Taxonomyoclif 特性，允许 nemoclaw <name> <command> 格式，无需 : 分隔符
Shields配置锁定状态 — 锁定/解锁代理配置，带自动 timeout
Policy Tier（策略层级）网络访问预设 — Restricted / Balanced / Open
Preset（预设）单个网络访问规则（如 brave、nous-web、dev-tooling）
Inference Profile蓝图中的声明式提供商配置（default/ncp/nim-local/vllm/routed）
Recover（恢复）重启网关但不打开 shell — 幂等操作
Rebuild（重建）重新创建沙箱：备份工作区 → 删除 → 用新镜像创建 → 恢复
Agent Variant（代理变体）OpenClaw vs Hermes — 影响默认值、预设、配置路径
Digest Pin蓝图中固定的 SHA256 镜像 digest，防止供应链攻击
Session State序列化的入门进度 — 支持 --resume 中断后恢复
Failure Layer分类的故障类型：docker_unreachable、sandbox_container_stopped、sandbox_dashboard_port_conflict
NIMNVIDIA 推理微服务 — 容器化模型端点
vLLM开源 LLM 服务引擎 — 本地推理选项
Ollama本地 LLM 运行时 — 无需 API key，支持 CPU/GPU
