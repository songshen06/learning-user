NemoClaw

在 NVIDIA OpenShell 沙箱中安全运行常驻 AI 代理的开源参考技术栈。通过单一 CLI 提供引导式入门、加固蓝图、推理路由、网络策略和生命周期管理。Alpha 项目 — Apache 2.0。

谁应该使用 NemoClaw

角色是否适合你能做什么
AI 应用开发者是在沙箱中运行代理进行开发
DevOps / 平台工程师是管理沙箱生命周期、策略和推理
注重安全的用户是出口控制、能力裁剪、配置锁定
企业管理员是多沙箱部署 + 策略分层
非技术终端用户否需要命令行，无 GUI 工作流
未安装 Docker否Docker 是必需的

前提条件

  • Node.js ≥ 22.16
  • npm ≥ 10
  • Docker（Engine、Desktop 或 Colima）正在运行
  • 4+ vCPU、8+ GB 内存（推荐 16 GB）、20+ GB 磁盘
  • Linux、macOS（Apple Silicon）、Windows WSL2 或 DGX Spark
  • 推理服务 API 密钥（OpenAI/Anthropic 等）或本地模型（Ollama/vLLM）

你能做什么

  • 在沙箱中运行 OpenClaw、Hermes 或 LangChain Deep Agents
  • 连接 11+ 推理提供商（NVIDIA、OpenAI、Anthropic、Gemini、Ollama、vLLM、NIM、自定义）
  • 用 3 个策略层级 + 自定义预设控制网络出口
  • 启用 Slack、Discord、Telegram 消息机器人
  • NVIDIA GPU 直通
  • 非交互式 / 脚本化安装（支持 CI/CD）
  • 监控健康状态、运行诊断、锁定/解锁配置

你不能做什么

  • 在没有 Docker 的情况下运行
  • 在裸 Windows 上运行（需要 WSL2）
  • 原地自动升级代理（必须重建沙箱）
  • 在 Hermes 中使用 Brave Search（仅 OpenClaw 支持）
  • 在同一个沙箱中混合多个代理
快速检查：运行 docker info && node --version — 两者都必须成功且版本正确。

功能概览

NemoClaw 将 AI 代理（OpenClaw、Hermes、LangChain Deep Agents）封装在 NVIDIA OpenShell 沙箱中 — 隔离的容器环境，具有网络出口控制、能力裁剪和推理路由。你通过单一 CLI（nemoclaw）管理完整生命周期：入门 → 连接 → 管理 → 恢复 → 重建 → 销毁。

组件用户所见
CLInemoclaw / nemohermes — 所有操作的单一命令
沙箱运行 AI 代理的隔离 Docker 容器
网关管理沙箱路由和推理的 OpenShell 网关
策略引擎网络出口控制 — Restricted / Balanced / Open 层级
推理路由将请求路由到 NVIDIA/OpenAI/Anthropic/Gemini/Ollama 等
Shields配置锁定状态 — 锁定/解锁代理配置

安装

预计耗时：5–15 分钟（取决于 Docker/Node 就绪状态）。

步骤 1：验证前提条件

node --version    # 必须 ≥ 22.16
npm --version     # 必须 ≥ 10
docker info       # Docker 必须正在运行
sudo apt-get install -y docker.io zstd binutils
sudo systemctl start docker
sudo usermod -aG docker $USER
newgrp docker

安装 Docker Desktop 或 Colima 并启动。安装 Xcode 命令行工具：

xcode-select --install

确保 WSL2 已启用并使用 Docker Desktop（WSL 后端）。参见 Windows 准备指南。

步骤 2：安装 NemoClaw

curl -fsSL https://www.nvidia.com/nemoclaw.sh | bash

Hermes 变体：

curl -fsSL https://www.nvidia.com/nemoclaw.sh | NEMOCLAW_AGENT=hermes bash

非交互式安装（CI/CD）：

curl -fsSL https://www.nvidia.com/nemoclaw.sh | \
  NEMOCLAW_NON_INTERACTIVE=1 \
  NEMOCLAW_ACCEPT_THIRD_PARTY_SOFTWARE=1 \
  bash

步骤 3：验证

nemoclaw --version
nemoclaw resources

首次运行 — 创建你的第一个沙箱

运行入门向导

nemoclaw onboard

向导引导你完成以下步骤：

  1. 提供商 — 选择 NVIDIA/OpenAI/Anthropic/Gemini/Ollama 等
  2. 凭证 — API 密钥（从不持久化到磁盘）
  3. 沙箱名称 — 默认 my-assistant
  4. 可选集成 — 网页搜索（Brave）、Slack、Discord、Telegram
  5. 策略层级 — Restricted / Balanced（默认）/ Open
  6. 预设自定义 — 包含/排除单个预设
  7. 沙箱构建 — ~2.4 GB 镜像（首次构建需数分钟）

连接

nemoclaw my-assistant connect

如果仍在构建中，connect 会轮询并显示进度。就绪后进入代理 shell。

代理专属交互方式：

  • OpenClaw：启动 TUI 聊天界面。用 /nemoclaw 执行快捷命令。
  • Hermes：进入沙箱 shell。使用仪表盘或端口 8642 上的 OpenAI 兼容 API。
  • LangChain Deep Agents Code：运行 dcode 进行交互式编码，或 dcode -n "总结这个仓库" 执行无头任务。无仪表盘 — 纯终端。用 nemoclaw onboard --agent langchain-deepagents-code 入门。
代理选择指南：OpenClaw 用于常驻聊天 + 消息机器人。Hermes 用于 OpenAI 兼容 API 接入。dcode 用于无头编码任务（类似 Claude Code）。

沙箱内斜杠命令（OpenClaw）

/nemoclaw          # 显示帮助
/nemoclaw status   # 显示沙箱 + 推理状态
/nemoclaw eject    # 显示回滚说明
/exit              # 离开聊天
首次构建需要时间：~2.4 GB 沙箱镜像需要构建和推送。后续入门运行更快（有缓存层）。

工作流

1. 查看沙箱状态
nemoclaw my-assistant status          # 文本输出
nemoclaw my-assistant status --json   # JSON（用于自动化）
nemoclaw list                         # 列出所有沙箱

显示：阶段（Ready/NotReady）、推理健康、GPU 状态、策略、已连接会话。

2. 连接并交互
nemoclaw my-assistant connect              # SSH 进入沙箱
nemoclaw my-assistant connect --probe-only # 仅健康检查

OpenClaw 内：输入消息与代理聊天。用 /exit 离开聊天，再 exit 回到主机 shell。

3. 非交互式运行命令
# 在沙箱中运行 shell 命令
nemoclaw my-assistant exec -- ls -la /sandbox

# 运行一次 OpenClaw 代理对话
nemoclaw my-assistant agent --agent work -m "总结 README.md"

# 指定工作目录
nemoclaw my-assistant exec --workdir /sandbox/workspace -- pwd
4. 恢复崩溃的沙箱
nemoclaw my-assistant recover    # 重启网关（幂等）
nemoclaw my-assistant status     # 验证恢复
nemoclaw my-assistant connect    # 重新连接

recover 重启沙箱内网关但不打开 shell。网关健康时运行也安全。

5. 重建沙箱（升级代理）
nemoclaw my-assistant rebuild --yes

复用沙箱名称和凭证。删除前备份工作区状态，重建后恢复。

6. 管理网络策略
nemoclaw my-assistant policy-add 
nemoclaw my-assistant policy-remove 
nemoclaw inference set --provider openai --model gpt-4o
层级访问范围
Restricted（受限）仅推理 + 核心工具
Balanced（平衡，默认）开发工具 + 网页搜索 + 包安装
Open（开放）广泛访问 + 消息平台
7. 锁定/解锁配置
nemoclaw my-assistant shields status
nemoclaw my-assistant shields up                    # 锁定配置
nemoclaw my-assistant shields down --timeout 5m     # 临时解锁
8. 启用消息集成
平台要求
SlackSLACK_BOT_TOKEN + SLACK_APP_TOKEN。可选：允许的用户/频道。
Discord可选服务器 ID、仅提及模式、用户白名单。
Telegram默认仅提及回复。TELEGRAM_REQUIRE_MENTION=0 回复所有消息。

在 nemoclaw onboard 时配置。消息令牌烘焙到沙箱镜像中，重建后保留。

卸载

./uninstall.sh --yes                        # 完全卸载
./uninstall.sh --yes --keep-openshell       # 保留 OpenShell
./uninstall.sh --yes --delete-models        # 同时删除模型

教程

  1. 安装：curl -fsSL https://www.nvidia.com/nemoclaw.sh | bash。用 nemoclaw --version 验证。
  2. 入门：运行 nemoclaw onboard。选择提供商，命名沙箱，选择 Balanced 层级。
  3. 连接：nemoclaw my-assistant connect。如仍在构建则等待 Ready 阶段。
  4. 聊天：输入消息与代理对话。用 /nemoclaw status 检查状态。输入 /exit 离开。
  5. 状态检查：从主机运行 nemoclaw my-assistant status。验证 Ready + 推理健康。
  6. 非交互式执行：nemoclaw my-assistant exec -- echo hello。验证输出。
  7. 恢复：nemoclaw my-assistant recover。验证幂等性（健康时运行也安全）。

练习

  1. 多沙箱：用不同提供商（如 Ollama）和 Restricted 层级入门第二个沙箱。验证两个沙箱都出现在 nemoclaw list 中。
  2. 非交互式入门：编写 bash 脚本非交互式安装 NemoClaw 并入门，指定提供商和策略层级。在 CI 中测试。
  3. 消息集成：入门时启用 Slack 或 Discord。从消息平台向机器人发送消息。验证代理响应。
  4. 策略管理：从 Restricted 层级开始。用 policy-add 添加预设。验证代理现在可以访问之前被阻止的服务。
  5. 恢复演练：杀掉网关进程。运行 nemoclaw <name> recover。验证沙箱无数据丢失地恢复到 Ready。
  6. 自定义 Dockerfile：用 --from ./Dockerfile.custom 入门，在沙箱中添加 Python 包。验证包可用。
