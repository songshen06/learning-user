NemoClaw

OpenShell sandbox manager for AI agents · TypeScript / oclif / Node.js ≥22.16 · v0.1.0 (Alpha)

What this repo does

NemoClaw wraps the openshell CLI with a higher-level orchestration layer: guided onboarding wizard, sandbox lifecycle (create/connect/exec/recover/rebuild/destroy), inference provider routing, network policy management, config lockdown (shields), and messaging platform integration. It provides guided onboarding, a hardened blueprint, routed inference, network policy, and lifecycle management through a single CLI.

Supported Agents

OpenClaw (default) — TUI chat agent with messaging bots · Hermes — OpenAI-compatible API service · LangChain Deep Agents Code (dcode) — headless terminal coding agent

Key differences: OpenClaw has dashboard + /nemoclaw slash commands. Hermes exposes port 8642 API. dcode has no dashboard, disables MCP at runtime, and runs via dcode / dcode -n "task". Config paths: /sandbox/.openclaw · /sandbox/.hermes · /sandbox/.deepagents.

Key Design Conventions

  • Thin commands, thick library: src/commands/ classes only parse args and validate; all logic is in src/lib/
  • Flexible taxonomy: oclif accepts nemoclaw <name> <command> without : separator
  • Agent-aware: OpenClaw vs Hermes differences handled at runtime via variant checks
  • Declarative blueprint: image digests, version ranges, and inference profiles are pinned in YAML
  • Co-located tests: .test.ts files sit next to their source in src/lib/
  • Credentials never touch disk: API keys registered to OpenShell gateway in-memory only

§Tutorial · Trace Tasks

1. Draw the stack diagram

Read README.md lines 1-20. Without reading code, draw: User → NemoClaw CLI → OpenShell → Docker → Agent → Provider. Label each arrow with what data crosses it.

2. Trace CLI dispatch

Read src/nemoclaw.ts (16 lines) → src/lib/cli/public-dispatch.ts → src/commands/onboard.ts. Trace how nemoclaw onboard --fresh flows from command line to src/lib/onboard.ts. Write 5 lines: each step, which file, what it does.

3. Understand blueprint digest pinning

Read nemoclaw-blueprint/blueprint.yaml fully. Find digest field and components.sandbox.image digest. Verify they match. Understand why both are pinned (supply chain security, issue #1438).

4. Trace onboard 8-step state machine

Read src/lib/onboard.ts. Find the 8 stages. Draw a state machine: which steps can resume, which must rerun on --resume. Find where session state is saved per step.

5. Trace recover idempotency

Read src/lib/runtime-recovery.ts. Find how recover determines "gateway already healthy" (idempotent exit) vs "needs restart". Compare with the auto-recovery path in connect.

6. Trace credential flow (no-disk guarantee)

Read src/lib/inference/ + src/lib/credentials/. Trace how NEMOCLAW_PROVIDER=openai passes an API key to the sandbox without writing to host disk. Verify the gateway-only storage claim.

7. Trace agent-aware policy filtering

Read src/lib/policy/. Find where Hermes presets (nous-web, nous-image) are added and where OpenClaw-only presets (brave) are excluded for Hermes. Draw the filtering pipeline.

8. Trace shields up/down lifecycle

Read src/lib/shields/. Find where shields up reads the saved restrictive policy. Trace shields down --timeout 5m → how the timeout triggers auto re-lock.

9. Trace messaging token baking

Read src/lib/messaging/. Find where Slack SLACK_APP_TOKEN is stored in a separate slack-app OpenShell provider (not mixed with bot token). Understand why Socket Mode needs both tokens.

10. Read the nemoclaw-user-guide skill

Read skills/nemoclaw-user-guide/SKILL.md. Find the MCP server URL and retrieval order (MCP → llms.txt → .md pages). Understand how this skill teaches AI assistants to fetch live docs.

§Exercises · Practice Tasks

Exercise 1 · Compare Docker-direct vs NemoClaw

Module: Mental Model  Difficulty: ★☆☆  Estimate: 30 min

List 5 additional values NemoClaw provides over running agents directly in Docker (hint: onboarding, policy, routing, shields, recovery). For each, identify which src/lib/ module implements it.

Exercise 2 · Add a custom CLI command

Module: CLI Architecture  Difficulty: ★★☆  Estimate: 1h

Create src/commands/dev-info.ts (minimal oclif command class). npm run build:cli then run nemoclaw dev-info. Verify auto-discovery works. Then add a --json flag.

Exercise 3 · Add a resource profile

Module: Blueprint System  Difficulty: ★★☆  Estimate: 30 min

Add ai-researcher profile (cpu: 80%, memory: 80%) to blueprint.yaml. Run npm run validate:configs. Verify schema validation passes.

Exercise 4 · Profile onboard timing

Module: Onboard Flow  Difficulty: ★★☆  Estimate: 1h + Docker

Set NEMOCLAW_TRACE=1, run nemoclaw onboard --fresh. Record per-step timestamps. Identify the slowest step (likely sandbox build / image push). Document optimization opportunities.

Exercise 5 · Crash recovery drill

Module: State & Recovery  Difficulty: ★☆☆  Estimate: 20 min

Kill the OpenShell gateway process. Run nemoclaw <name> recover. Observe: detection → restart → verification. Run recover again to verify idempotency.

Exercise 6 · Compare exec vs docker exec

Module: Sandbox Lifecycle  Difficulty: ★☆☆  Estimate: 15 min

Run nemoclaw <name> exec -- echo $HOME (should print /sandbox). Then run docker exec <container> echo $HOME (prints /root). Document why NemoClaw exec is safer for agent config resolution.

Exercise 7 · Switch inference provider at runtime

Module: Inference Routing  Difficulty: ★★☆  Estimate: 30 min

Onboard with NVIDIA cloud. Then run nemoclaw inference set --provider ollama --model llama3. Trace how the gateway route changes. Verify status reflects the new provider.

Exercise 8 · Add and remove policy presets

Module: Network Policy  Difficulty: ★★☆  Estimate: 30 min

Onboard with Restricted tier. Add a preset with policy-add. Verify the agent can now reach the previously-blocked service. Then remove it and verify access is blocked again.

Exercise 9 · Shields lifecycle test

Module: Security & Shields  Difficulty: ★☆☆  Estimate: 15 min

Run shields up, then config get (verify locked). Run shields down --timeout 1m. Wait 1 minute. Verify auto re-lock by running shields status.

Exercise 10 · Write a dev-guide skill

Module: Agent Skills  Difficulty: ★★☆  Estimate: 1h

Following nemoclaw-user-guide/SKILL.md format, write nemoclaw-dev-guide SKILL.md (30-50 lines): frontmatter / When to Use / First Command. Place in .agents/skills/. Analyze: what developer request would trigger it?
