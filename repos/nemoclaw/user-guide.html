NemoClaw

Open source reference stack for running always-on AI agents safely inside NVIDIA OpenShell sandboxes. Guided onboarding, hardened blueprint, routed inference, network policy, and lifecycle management through a single CLI. Alpha project — Apache 2.0.

Who should use NemoClaw

PersonaFit?What you do

DevOps / Platform EngineerYesManage sandbox lifecycle, policies, inference
Security-conscious userYesEgress control, capability drops, shields
Enterprise adminYesMultiple sandboxes with policy tiers
Non-technical end userNoCLI-first, no GUI workflow
No Docker installedNoDocker is required

Prerequisites

  • Node.js ≥ 22.16
  • npm ≥ 10
  • Docker (Engine, Desktop, or Colima) running
  • 4+ vCPU, 8+ GB RAM (16 GB recommended), 20+ GB disk
  • Linux, macOS (Apple Silicon), Windows WSL2, or DGX Spark
  • Inference provider API key (OpenAI/Anthropic/etc.) or local model (Ollama/vLLM)

What you can do

  • Run OpenClaw, Hermes, or LangChain Deep Agents in sandboxes
  • Connect 11+ inference providers (NVIDIA, OpenAI, Anthropic, Gemini, Ollama, vLLM, NIM, custom)
  • Control network egress with 3 policy tiers + custom presets
  • Enable Slack, Discord, Telegram messaging bots
  • GPU passthrough for NVIDIA GPUs
  • Non-interactive / scripted installs for CI/CD
  • Monitor health, run diagnostics, lock/unlock config

What you cannot do

  • Run without Docker
  • Run on bare Windows (needs WSL2)
  • Auto-upgrade agents in-place (must rebuild sandbox)
  • Use Brave Search with Hermes (OpenClaw-only)
  • Mix multiple agents in the same sandbox
Quick check: Run docker info && node --version — both must succeed with correct versions.

What it does

NemoClaw wraps AI agents (OpenClaw, Hermes, LangChain Deep Agents) in NVIDIA OpenShell sandboxes — isolated container environments with network egress control, capability drops, and routed inference. You interact through a single CLI (nemoclaw) that handles the full lifecycle: onboard → connect → manage → recover → rebuild → destroy.

ComponentWhat users see
CLInemoclaw / nemohermes — single command for all operations
SandboxIsolated Docker container running the AI agent
GatewayOpenShell gateway managing sandbox routing and inference
Policy EngineNetwork egress control — Restricted / Balanced / Open tiers
Inference RoutingRoutes requests to NVIDIA/OpenAI/Anthropic/Gemini/Ollama/etc.
ShieldsConfig lockdown posture — lock/unlock agent configuration

Install

Estimated time: 5–15 min (depending on Docker/Node readiness).

Step 1: Verify prerequisites

node --version    # Must be ≥ 22.16
npm --version     # Must be ≥ 10
docker info       # Docker must be running
sudo apt-get install -y docker.io zstd binutils
sudo systemctl start docker
sudo usermod -aG docker $USER
newgrp docker

Install Docker Desktop or Colima and start it. Install Xcode CLI tools:

xcode-select --install

Ensure WSL2 is enabled with Docker Desktop (WSL backend). See the Windows Preparation Guide.

Step 2: Install NemoClaw

curl -fsSL https://www.nvidia.com/nemoclaw.sh | bash

Hermes variant:

curl -fsSL https://www.nvidia.com/nemoclaw.sh | NEMOCLAW_AGENT=hermes bash

Non-interactive (CI/CD):

curl -fsSL https://www.nvidia.com/nemoclaw.sh | \
  NEMOCLAW_NON_INTERACTIVE=1 \
  NEMOCLAW_ACCEPT_THIRD_PARTY_SOFTWARE=1 \
  bash

Step 3: Verify

nemoclaw --version
nemoclaw resources

First Run — Onboard your first sandbox

Run the wizard

nemoclaw onboard

The wizard walks you through 8 steps:

  1. Provider — choose NVIDIA/OpenAI/Anthropic/Gemini/Ollama/etc.
  2. Credential — API key (never persisted to disk)
  3. Sandbox name — default my-assistant
  4. Optional integrations — web search (Brave), Slack, Discord, Telegram
  5. Policy tier — Restricted / Balanced (default) / Open
  6. Preset customization — include/exclude individual presets
  7. Sandbox build — ~2.4 GB image (first build takes minutes)

Connect

nemoclaw my-assistant connect

If still building, connect polls and shows progress. Once ready, you're in the agent shell.

Agent-specific interaction:

  • OpenClaw: TUI chat interface launches. Use /nemoclaw for quick commands.
  • Hermes: Sandbox shell. Use dashboard or OpenAI-compatible API on port 8642.
  • LangChain Deep Agents Code: Run dcode for interactive coding, or dcode -n "Summarize this repository" for headless tasks. No dashboard — pure terminal. Onboard with nemoclaw onboard --agent langchain-deepagents-code.
Choosing an agent: OpenClaw for always-on chat + messaging bots. Hermes for OpenAI-compatible API access. dcode for headless coding tasks (similar to Claude Code).

In-sandbox slash commands (OpenClaw)

/nemoclaw          # Show help
/nemoclaw status   # Show sandbox + inference state
/nemoclaw eject    # Show rollback instructions
/exit              # Leave chat
First build takes time: The ~2.4 GB sandbox image needs to be built and pushed. Subsequent onboard runs are faster (cached layers).

Workflows

1. Check sandbox status
nemoclaw my-assistant status          # Text output
nemoclaw my-assistant status --json   # JSON for automation
nemoclaw list                         # All sandboxes

Shows: phase (Ready/NotReady), inference health, GPU state, policy, connected sessions.

2. Connect and interact
nemoclaw my-assistant connect              # SSH into sandbox
nemoclaw my-assistant connect --probe-only # Health check only

Inside OpenClaw: type messages to chat. Use /exit to leave chat, then exit for host shell.

3. Run commands non-interactively
# Shell command in sandbox
nemoclaw my-assistant exec -- ls -la /sandbox

# One OpenClaw agent turn
nemoclaw my-assistant agent --agent work -m "Summarize README.md"

# With working directory
nemoclaw my-assistant exec --workdir /sandbox/workspace -- pwd
4. Recover a crashed sandbox
nemoclaw my-assistant recover    # Restart gateway (idempotent)
nemoclaw my-assistant status     # Verify recovery
nemoclaw my-assistant connect    # Reconnect

recover restarts the in-sandbox gateway without opening a shell. Safe to run when already healthy.

5. Rebuild sandbox (upgrade agent)
nemoclaw my-assistant rebuild --yes

Reuses sandbox name + credentials. Backs up workspace state before delete, restores after rebuild.

6. Manage network policies
nemoclaw my-assistant policy-add 
nemoclaw my-assistant policy-remove 
nemoclaw inference set --provider openai --model gpt-4o
TierAccess
RestrictedInference + core tooling only
Balanced (default)Dev tooling + web search + packages
OpenBroad access + messaging
7. Lock/unlock configuration
nemoclaw my-assistant shields status
nemoclaw my-assistant shields up                    # Lock config
nemoclaw my-assistant shields down --timeout 5m     # Temp unlock
8. Enable messaging integrations
PlatformRequirements
SlackSLACK_BOT_TOKEN + SLACK_APP_TOKEN. Optional: allowed users/channels.
DiscordOptional server ID, mention-only mode, user allowlist.
TelegramMention-only by default. TELEGRAM_REQUIRE_MENTION=0 for all messages.

Configured during nemoclaw onboard. Messaging tokens are baked into the sandbox image and persist across rebuilds.

Uninstall

./uninstall.sh --yes                        # Full uninstall
./uninstall.sh --yes --keep-openshell       # Keep OpenShell
./uninstall.sh --yes --delete-models        # Also delete models

Tutorial

  1. Install: curl -fsSL https://www.nvidia.com/nemoclaw.sh | bash. Verify with nemoclaw --version.
  2. Onboard: Run nemoclaw onboard. Choose a provider, name your sandbox, pick Balanced tier.
  3. Connect: nemoclaw my-assistant connect. Wait for Ready phase if still building.
  4. Chat: Type a message to the agent. Use /nemoclaw status to check state. Type /exit to leave.
  5. Status check: From host: nemoclaw my-assistant status. Verify Ready + healthy inference.
  6. Non-interactive exec: nemoclaw my-assistant exec -- echo hello. Verify output.
  7. Recover: nemoclaw my-assistant recover. Verify it's idempotent (safe when healthy).

Exercises

  1. Multi-sandbox: Onboard a second sandbox with a different provider (e.g., Ollama) and Restricted tier. Verify both appear in nemoclaw list.
  2. Non-interactive onboard: Write a bash script that installs NemoClaw and onboards non-interactively with a specific provider and policy tier. Test in CI.
  3. Messaging integration: Enable Slack or Discord during onboard. Send a message to the bot from the messaging platform. Verify the agent responds.
  4. Policy management: Start with Restricted tier. Add a preset with policy-add. Verify the agent can now reach the previously-blocked service.
  5. Recovery drill: Kill the gateway process. Run nemoclaw <name> recover. Verify the sandbox returns to Ready without data loss.
  6. Custom Dockerfile: Onboard with --from ./Dockerfile.custom that adds a Python package to the sandbox. Verify the package is available inside.
