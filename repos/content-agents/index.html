content-agents

NVIDIA AI-driven 3D content automation framework · VLM-based USD asset analysis · v0.4.3

What this repo does

Uses VLM (Vision-Language Model) to analyze multi-view renders of USD assets, automatically assign materials, classify physics properties, generate textures, and validate generated content. 4 agents (Material / Physics / Texture / Validation) each available as CLI + REST service. At its core: the "3D Render → VLM Sees → Reasons → Modifies USD" agentic pipeline.

All agents marked Beta or Research Preview. Linux/WSL2 only — no native Windows/macOS.

Key Design Conventions

  • Tool = func + ToolSpec: decorator registration, import-triggered
  • VLM calls tools via LangChain function-calling: humans don't call tools directly
  • YAML DSL describes pipelines: config structure reused across 4 agents
  • Render → Predict → Apply → Validate: standard closed loop
  • Data URI by default: rendered images base64 inline (no S3 needed)
  • OpenTelemetry full tracing: every tool invocation auto-spans

1. Draw the 4-agent flowchart

3. Trace register_tool's registration chain

In tools/base.py, find register_tool. Observe: (1) how it receives ToolSpec; (2) what data structure _TOOLS_REGISTRY is; (3) whether it returns wrapper or function. Then in tools/__init__.py:18-21 watch import trigger registration. Draw: import → decorator → dict insert chain.

4. Trace two registries' interaction

Search tools/base.py for read/write locations of _TOOLS_REGISTRY. In tools/__init__.py's register_all_tools(), see how it simultaneously operates tool registry and display registry. In tools/cv/__init__.py see @register_tool usage. Draw complete timeline.

5. Step through material pipeline

Open unified_example.yaml. From ladder.usd to validation, write one line per step: "what this step does" (inferring from YAML only). Cross-reference README descriptions to verify.

6. Compare Material vs Physics config

7. Draw 3-agent data flow

Draw Material → Texture → Validation data flow. For each arrow write one line: "input format." Verify: can Texture run before Material? Write one sentence explaining why.

8. Unpack validation's request → plan → result

Open any YAML under validation_agent/examples/configs/. Find validation_request/plan/policy fields, derive: task → plan → criteria → judge decision chain. Cross-check with examples/README.md.

9. Read a non-material skill

§Exercises · Practice Tasks

Exercise 1 · Predict how an asset will be processed

Module: Mental Model  Difficulty: ★☆☆☆  Estimate: 30 min

Pick a public USD (e.g., USDA Kitchen Set). Predict: which parts does Material Agent assign which materials to? What physics types does Physics Agent classify? Which faces does Texture Agent flag as solid-color and need textures? What validations does Validation Agent perform? Write a one-page prediction table. Later re-run and compare predictions vs actuals.

Exercise 2 · install_all_cli.sh

Module: Dual-Mode Arch  Difficulty: ★★☆  Estimate: 1h

Write install_all_cli.sh: from scratch (no repo) to all 4 agent CLIs showing --help. clone → uv venv → install core+4 agents → fetch build → verify. Must at least run material-agent --help.

Exercise 3 · Add a custom tool

Module: Core Library  Difficulty: ★★☆  Estimate: 1h

Under tools/cv/, create fake_tool.py. Write DescribeColorTool: input_model ColorInput(color:str) → output_model ColorOutput(description:str), @register_tool registered. Add import in tools/__init__.py and tools/cv/__init__.py. Verify register_all_tools() returns your tool.

Exercise 4 · inspect_tools.py + call_tool.py

Module: Tool Registry  Difficulty: ★★☆  Estimate: 1h

Write inspect_tools.py (import register_all_tools, print all tools' name/input/output/tag). Then write call_tool.py — for get_dominant_colors_tool, construct valid input, call Tool.run(), verify output.

Exercise 5 · Modify unified_example for your asset

Module: Material Agent  Difficulty: ★★★  Estimate: 1.5h + GPU

Copy unified_example.yaml as my_asset.yaml, change 3 things: (1) usd_path to your USD; (2) backend per your API key; (3) disable optimize/apply, run to predict only. See what materials VLM selects for your asset. Without GPU, at least use yaml.safe_load to validate structure.

Exercise 6 · Manual Physics Agent

Module: Physics Agent  Difficulty: ★☆☆  Estimate: 20 min

Take 3 photos of any desktop object. You act as VLM for Physics prediction: material type / component function / mass/density/friction/deformability / asset type. Write structured results.

Exercise 7 · Scan empty texture slots

Module: Texture Agent  Difficulty: ★★☆  Estimate: 45 min

For a USD with existing material bindings, use pxr.UsdShade to walk prims, count "has material binding but no texture file path." Without USD, understand discover command's role.

Exercise 8 · Human validator

Module: Validation Agent  Difficulty: ★☆☆  Estimate: 20 min

Pick any 3D render. Do a look-right judge: What do you see? What do you expect? Verdict pass/fail? One sentence reason. Think: can a VLM make this judgment? When would a VLM misjudge?

Exercise 9 · Write a minimal agent skill

Module: Agent Skills  Difficulty: ★★☆  Estimate: 1h

Following material-agent-cli SKILL.md format, write my-first-skill SKILL.md (30-50 lines): frontmatter / When to Use / First Command. Place under .agents/skills/. Analyze: if Claude Code loads this skill, what user request triggers it? How does it differ from CLAUDE.md per-scenario dispatch?

Exercise 10 · Modify render config

Module: Render  Difficulty: ★★☆  Estimate: 45 min

Use yaml.safe_load to read unified_example.yaml's renderer, change 3 items: (1) backend remote → local; (2) resolution 512 → 1024; (3) add "+x-y+z" view. Explain how each affects VLM prediction quality. With GPU, run once and measure actual differences.
