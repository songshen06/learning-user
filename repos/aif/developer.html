aif-pipeline-samples

NVIDIA 官方样本仓库 · CAD → SimReady USD 资产流水线 · 数字孪生 / AI Factory 场景

这个仓库做什么

把 CAD 文件（STEP / JT / Creo / DGN）批量转换成 SimReady USD 资产，并提供一条 4 阶段流水线：Convert → Optimize → Validate → Metadata。仓库本身是 samples（参考实现），真正干活的是 Omniverse Kit / Scene Optimizer / asset-validator，本仓库把这些能力封装成 CLI + 可复用 preset + 自定义校验器。

关键设计约定

  • CLI 是薄包装：每个子命令 lazy-import 一个 commands/<name>.py 的 run_* 函数
  • Config 三级优先：显式 --config > 项目 ./aif-pipeline.yaml > 用户 ~/.aif-pipeline/config.yaml
  • 所有命令需 uv run 前缀（或激活 .venv）
  • 非破坏式：每步独立输出目录（Converted/、Optimized/）
  • metadata 是子层：写到 *_Properties.usda 作为 sublayer 组合进主资产
  • OAV 校验 subprocess：run 命令通过 uv run --directory oav validate 调用

§推荐学习路径（8 步）

按顺序学，每一步都建立在前一步的心智模型上。前 2 步是概念，3-7 步是流水线核心，第 8 步是按需进阶。

  1. 心智模型：先建立 USD / SimReady / AIF / 数字孪生的概念
    → 模块① · 读 README.md + CLAUDE.md + docs/about/*
  2. 整体工作流：Convert → Optimize → Validate → Metadata，先理解输入输出，不深入
    → CLAUDE.md "Core Workflow" 段
  3. CLI 总览：6 个子命令、config 优先级、uv run 约定
    → 模块② · cli/README.md
  4. CLI 内部实现：click 命令树、lazy import、Config 类、run 编排
    → 模块③ · cli/aif_pipeline/{cli.py,commands/,config.py}
  5. Scene Optimizer preset：12 步通用 preset + pythonScript 处理器
    → 模块④ · so/generic/generic_preset.json + lib/*.py
  6. OAV 校验规则：每条规则一个文件，AIFMetadataChecker 是桥梁
    → 模块⑤ · oav/aif_validators/
  7. Metadata 与 AIF profile：aif:core: / aif:spec: + 4 种设备模板
    → 模块⑥ · metadata/templates/
  8. 进阶专题：Pipeline 脚本 / Web UI / Connection points / Agent rules
    → 模块⑦⑧⑨⑩ · 按需深入

§教程 · 跟读任务（Trace Tasks）

每个模块的"跟读任务"——按学习路径顺序串成一条完整跟读教程。做完这条线 = 真正理解了仓库。

① 建立 CAD → SimReady 心智模型

依次读 docs/about/what-is-usd.md（5 分钟）→ docs/about/what-is-simready.md（5 分钟）→ docs/about/cad-vs-simulation-assets.md（5 分钟）。然后用 1 段话（不超过 100 字）向一个完全外行的朋友解释"为什么 NVIDIA 需要这个仓库"。如果能解释清楚，说明心智模型建立了。

② 熟悉 CLI 命令面

跑 aif-pipeline --help 和 aif-pipeline run --help，对照 cli/README.md "Commands" 段逐一核验每个 flag 是否真实存在；并在 cli/aif_pipeline/cli.py 找到每个 @cli.command() / @config.command() 装饰器对应的 line，确认 README 与源码一致。

③ 追 CLI 内部实现：一次 spec 路径解析

在 cli.py 找 convert 命令（cli.py:120），跟到 cli.py:138 的 spec or config.get_conversion_spec()，再跳进 config.py:271 的 get_conversion_spec()，最后看 config.py:280 推算 repo root 的 Path(__file__).parent.parent。完整理解一次 spec 路径从空到默认值的全过程。

④ 解码 preset 的 pythonScript

跑 echo '<generic_preset.json 第 11 行的 python 字段>' | base64 -d 解码，对照 so/generic/lib/deduplicate_hierarchies_by_display_name.py 的开头注释，确认 loader 是通过 AIF_PIPELINE_SAMPLES_ROOT 环境变量拼路径、再 exec(compile(...)) 调用 process_duplicate_hierarchies() 函数。然后在 deduplicate_hierarchies_by_display_name.py:1142 找 process_duplicate_hierarchies() 主入口，看 use_payloads / merge_prototype_hierarchies 两个 flag 如何切换 3 种模式。

⑤ 追 OAV 校验调用链

从 cli run 的 validate 步骤开始追：cli/aif_pipeline/commands/run.py:31 → _run_oav_validate → subprocess uv run validate --category AIF → oav/aif_validators/__main__.py（入口）→ __init__.py:10-23（注册所有规则）→ 任一规则的 CheckStage。完整还原"CLI 调用 → subprocess → 规则注册 → 实际检查"链路。

⑥ 走通一次 metadata 创建与应用

跑 aif-pipeline metadata create --type cdu --output /tmp/cdu.json，打开生成的 JSON，对照 metadata/templates/cdu_template.py 的 get_cdu_properties() 返回值，逐一核对每个 aif:spec:* 字段。然后跑 aif-pipeline metadata apply /tmp/cdu.json --output /tmp/cdu.usda --prim CDU_01，用文本编辑器打开 /tmp/cdu.usda，观察 USD 层文件结构（sublayer、defaultPrim、attributes）。

⑦ 对照 CLI 命令与底层脚本

打开 scripts/cad_convert.py，找到 (a) 解析输入目录的循环、(b) 构造 Kit subprocess 命令的部分、(c) --num_concurrent 参数如何映射到并发。对照 cli/aif_pipeline/commands/convert.py 的 run_convert()，看 CLI 是怎么把 --concurrent flag 翻译成脚本的 --num_concurrent。这能解释为什么 README 同时有两个参数名。

⑧ 用 Web UI 构建并对比 preset

启动 server 模式，浏览器打开 index.html，从左侧库拖 editStageMetrics 到中间，在右侧把 metersPerUnit 改为 0.01、upAxis 改为 1（Y）。点 Save，下载 JSON。打开 JSON 与 so/generic/generic_preset.json 的第 1 个操作对比，验证：字段名、值类型、顺序都完全一致。

⑨ 核对 connection points 命名约定

读 docs/workflows/connection-points.md 的命名约定表。然后打开 assets/ 下的样本 USD（如果有），用 usdcat 或 USDView 找出所有看起来像 connection point 的 prim（按命名前缀过滤），核对它们的几何类型（plane/disk）是否与文档一致。

⑩ 走通 agent 规则的调度闭环

读 CLAUDE.md 的 "Agent Behavior > Validation Failure Fix Loop" 段（约 line 134）。然后读 .cursor/rules/usd-universal.mdc 的开头 symptom-to-fix 表。最后回看 oav/aif_validators/aif_metadata_checker.py 的 COMMON_ATTRIBUTES（line 55）。完整还原一次"validation 报 AIFMetadataChecker failed → CLAUDE.md 路由到读 usd-universal.mdc → 找到 symptom 对应的 metadata 缺失修复 → 在 preset 加 metadata 属性"的闭环。

§练习 · 实战检查点（Practice Tasks）

每个练习都是一次动手操作。做完任意 5 个就具备改动这个仓库的基础能力。

练习 1 · 写一个 convert_only.sh 自动化脚本

模块：CLI 总览　难度：★☆☆　预计耗时：30 分钟

写一个最小 shell 脚本 convert_only.sh：接受 3 个参数（input_dir / output_dir / cad_format），根据 cad_format 自动选择 spec（creo/jt/dgn），先跑 config show 校验 Kit，再跑 convert --skip-existing。脚本必须在 Kit 未配置时退出码非 0 并打印提示。

练习 2 · 给 CLI 加 config export 子命令

模块：CLI 内部　难度：★★☆　预计耗时：45 分钟

新增一个 aif-pipeline config export <output.yaml> 子命令，调用现有 Config.save() 但写入用户指定路径（不覆盖活动 config）。需要在 cli.py 加 @config.command('export')，在 commands/config_cmd.py 加 run_config_export(output_path)，并实现"先复制当前 data，再 save 到 output"的逻辑。验收：跑完后能在指定路径看到带注释的 YAML。

练习 3 · 定制一个不减面的 preset

模块：Scene Optimizer　难度：★★☆　预计耗时：45 分钟

复制 generic_preset.json 为 generic_preset_no_decimate.json，移除第 4 步 decimateMeshes（保留减面会导致精度损失的场景常用）。然后用 aif-pipeline optimize input/ output/ --preset generic_preset_no_decimate.json 对一个样本 USD 跑一遍，比较输出顶点数与原版差异。最后思考：如果调换第 2 步（dedup hierarchies）和第 3 步（meshCleanup）会发生什么？写一段假设并验证。

练习 4 · 写一条新的 OAV 校验规则

模块：OAV Validators　难度：★★☆　预计耗时：1 小时

在 oav/aif_validators/ 新增 default_prim_is_xform.py，写一个 DefaultPrimIsXformChecker：检查 stage 的 defaultPrim 是 Xform 类型。提示：用 stage.GetDefaultPrim().GetTypeName()，期望值 "Xform"。注册到 "AIF" category，更新 __init__.py，然后跑 uv run --directory oav validate --rule DefaultPrimIsXformChecker /path/to/sample.usd 验证。最后给 assets/ 下的样本 USD 跑 --category AIF 看你的新规则是否出现在报告里。

练习 5 · 对比 4 种设备模板的属性集

模块：Metadata　难度：★★☆　预计耗时：1 小时

写一个 Python 脚本 compare_templates.py，对比 4 种设备模板（CDU/CRAH/UPS/GB300）的 aif:spec:* 属性集合，输出一个 markdown 表格列出"哪些属性是某设备独有 / 哪些是 4 种都有"。提示：import 4 个 get_*_properties() 函数，做 set 运算。这能帮你建立"为什么 GB300 只有 8 个专属属性而 CDU 有 61 个"的直觉。

练习 6 · 写一个脱离 Kit 的 USD prim 列举器

模块：Pipeline Scripts　难度：★★☆　预计耗时：45 分钟

写一个 scripts/examples/list_default_prims.py：接受一个 USD 文件路径，打开 stage，遍历所有根级 prim，打印每个 prim 的 path / typeName / 是否是 defaultPrim。要求能脱离 Kit 运行（用 pxr.Usd 即可，不需要 omni.*）。这是连接本模块和 OAV 模块的桥梁练习（validator 也读 defaultPrim）。

练习 7 · 用 Web UI 复刻 generic preset 前 5 步

模块：Asset Processor Web UI　难度：★★☆　预计耗时：1 小时

用 UI 拖出 generic_preset.json 的前 5 步（editStageMetrics + pythonScript(dedup) + meshCleanup + decimateMeshes + generateNormals），保存为 my_first_preset.json。然后在 cli 跑 aif-pipeline optimize <sample_usd> <output> --preset my_first_preset.json。如果没装 Kit，至少跑 python -c "import json; print(json.dumps(json.load(open('my_first_preset.json')), indent=2)[:500])" 验证 JSON 结构合法，并尝试 base64 解码 pythonScript 字段看 loader 代码。

练习 8 · 手工添加 connection points

模块：Connection Points　难度：★★★　预计耗时：1.5 小时

为某个简单设备（一个立方体 mesh，representing CDU）在 USD 里手工添加 2 个 connection point prim：1 个 thermal 进水口（plane，位于顶面）、1 个 thermal 出水口（plane，位于底面），命名遵循 docs/workflows/connection-points.md 约定。然后用 aif-pipeline validate <file> 跑校验，观察是否有规则报错（可能没有专门的 connection point 校验规则，思考为什么 —— 是 schema 还是 prim 命名约束）。

练习 9 · 写一份 agent 处理流程文档

模块：Agent Knowledge Rules　难度：★★☆　预计耗时：1 小时

模拟一个 agent 场景：用户报告"我的 CRAH 资产 validation 显示 AIFMetadataChecker 失败"。写一份 agent 处理流程文档（markdown），列出：(a) 应读哪些规则文件及顺序（参考 CLAUDE.md 的调度）、(b) 可能的根因清单（参考 aif_metadata_checker.py 的 _validate_metadata）、(c) 修复步骤（结合 metadata apply 命令 + 重跑 validate）。这份文档将构成你自己 agent workflow 的模板。

练习 10 · CAD 转换问题预判（无代码）

模块：心智模型　难度：★☆☆　预计耗时：30 分钟

挑一个真实的 CAD 文件（任选 .step 或 .jt，可从公开样本库下载）。基于本模块学到的概念，预判它在转换成 USD 后会有哪些问题（顶点过多？单位错？朝向错？无材质？无元数据？）。把预判写下来。后续学完其他模块后，回看你的预判是否被 validate 命令的报告证实。这个练习建立"工程预判"能力。
