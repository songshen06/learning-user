aif-pipeline 使用者指南

把 CAD 文件变成 NVIDIA Omniverse / 数字孪生可用的 SimReady USD 资产。不读源码、不改代码，只跑命令。

这份指南适合你吗？

✅ 适合 —— 如果你想：

  • 把 STEP / JT / Creo / DGN 文件批量转成 USD
  • 给客户/项目交付符合 NVIDIA SimReady 标准的资产
  • 优化 USD 文件（减面、清拓扑、修法线）让 Omniverse 跑得动
  • 校验 USD 是否合规、是否符合 AIF（AI Factory）元数据规范
  • 给设备资产（CDU/CRAH/UPS/GB300 机柜）添加标准元数据

⚠️ 可能不适合 —— 如果你是：

  • 没有 NVIDIA RTX GPU → Convert/Optimize 必须用 Kit，Kit 必须有 RTX。无 GPU 只能跑 OAV 校验。
  • 想实时渲染 USD → 这是离线流水线工具，不是渲染器。渲染请用 USD Composer / USDView。
  • 想直接编辑 USD → 这是命令行批处理工具。手工编辑用 USD Composer GUI。
  • 想改工具自身的行为 → 那是开发者向，请看 开发者指南。

§这工具能做什么 / 不能做什么

✅ 能做

能力说明对应命令

不能做替代方案

§5 分钟看懂全局

整个工具就一条流水线，4 个阶段，每个阶段独立可单独跑：

CAD.step/.jt/.prt/.dgn
→
Convert→ .usd
→
Optimize减面/清理
→
Validate查合规
→
Metadata加属性

每个阶段的输入输出都是独立的 USD 文件。可以只跑其中一两个阶段，也可以一键串起来。

最小可用流程（3 个命令搞定）

# 1. 一次性配置：告诉工具你的 Kit 装在哪
aif-pipeline config add my_kit --from "D:/build/kit-app-template"

# 2. 转换 + 优化 + 校验（一气呵成）
aif-pipeline run input_cad/ output/ --spec scripts/data/creo_spec.json --preset so/generic/generic_preset.json

# 3. 给某个 CDU 设备加元数据
aif-pipeline metadata create --type cdu --output cdu.json
# ...人工填值...
aif-pipeline metadata apply cdu.json --output CDU_01_Properties.usda --prim CDU_01
不想敲命令？ 这个工具还有一个 Web UI（asset_processor/）。浏览器拖拽就能跑同样的事，详见 Web UI 章节。

①安装（一次性，约 30 分钟）

前提条件

项要求
操作系统Windows 10/11 或 Linux（Ubuntu 20.04+）不支持 macOS
GPUNVIDIA RTX GPU（Convert/Optimize/Kit-Validate 必需）
内存16 GB+ 推荐（每个 Kit 实例占 4-8 GB）
磁盘~20 GB（Kit SDK + USD Composer build）
Python3.10–3.12（uv 会自动下载，无需手工装）
Git需要（clone 仓库用）
Windows 特别PowerShell 执行策略：第一次报 UnauthorizedAccess 时跑 Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned

②配置 Kit 路径（关键一步）

这是从"装好了"到"能跑了"之间唯一的拦路虎。CLI 必须知道你的 Kit 装在哪。

最关键的认知：--from 后面跟的是 Kit project root —— 含 repo.bat / repo.sh 的目录，不是 _build/ 或它下面的子目录。工具会自动从 project root 找到 kit.exe。 
# Kit App Template 装的：
aif-pipeline config add kat_109 --from "D:/build/kit-app-template"

# NGC 手动装的：
aif-pipeline config add ngc_109 --from "D:/build/ngc/USD_Composer_109.0.3"
# Kit App Template 装的：
aif-pipeline config add kat_109 --from ~/kit-app-template

# NGC 手动装的：
aif-pipeline config add ngc_109 --from ~/build/ngc/USD_Composer_109.0.3

成功的输出长这样：

OK Kit executable: D:\build\kit-app-template\_build\windows-x86_64\release\kit\kit.exe
OK Release directory: D:\build\kit-app-template\_build\windows-x86_64\release
OK Configuration saved to: C:\Users\<you>\.aif-pipeline\config.yaml

验证配置

aif-pipeline config show

应该看到 kit.path 和 kit.release_dir 都有值（不是 null）。如果是 null，说明 --from 路径不对，回去重做。

管理多个 Kit 版本（按需）

# 加多个 Kit 配置
aif-pipeline config add kat_109 --from ~/kit-app-template
aif-pipeline config add ngc_110 --from ~/build/ngc/USD_Composer_110.0.0

# 看所有
aif-pipeline config list

# 切换默认
aif-pipeline config use ngc_110

# 单次命令用某个 config，不改默认
aif-pipeline --config ngc_109 convert input/ output/ --spec spec.json

③第一次跑（端到端）

准备一个含 CAD 文件的目录，跑这一条命令完成 Convert + Optimize + Validate：

aif-pipeline run input_cad/ output/ \
  --spec scripts/data/creo_spec.json \
  --preset so/generic/generic_preset.json

跑完会在 output/ 看到：

output/
├── Converted/    # CAD → USD 的原始结果
└── Optimized/    # 经过 generic_preset.json 优化后的结果

校验结果会直接打印在终端。看到 PASSED 就说明合规。

spec 文件怎么选

你的 CAD 格式扩展名用哪个 spec
Creo / PTC.prt .asmscripts/data/creo_spec.json
JT.jtscripts/data/jt_spec.json
MicroStation DGN.dgnscripts/data/dgn_spec.json
STEP / 其他.step .stp先用 creo_spec.json 试，不行查 CAD Converter 文档
不想跑全部 3 步？ 用 --steps 自定义：--steps convert,optimize 跳校验；--no-validate 也是跳校验的简写。

④阶段 1 · Convert（CAD → USD）

什么时候单独跑

  • 只想拿到原始 USD，不想优化
  • 批量转换大量文件，想用高并发
  • 之前中途中断了，想续跑

典型命令

# 标准批量
aif-pipeline convert input_cad/ output_usd/ \
  --spec scripts/data/creo_spec.json

# 高并发 + 跳过已转过的（断点续跑）
aif-pipeline convert input_cad/ output_usd/ \
  --spec scripts/data/creo_spec.json \
  --concurrent 64 \
  --skip-existing

# 超时控制（复杂装配可能很慢）
aif-pipeline convert input_cad/ output_usd/ \
  --spec scripts/data/creo_spec.json \
  --timeout 7200

常用 flag

flag含义默认
--specCAD 格式 spec（必填或在 config 设）config 的 conversion.spec
--concurrent并发进程数64
--timeout单文件超时秒数7200（2 小时）
--skip-existing已转过的跳过（断点续跑神器）false
需要 Kit：convert 通过 Kit 的 CAD Converter 扩展干活。每个并发进程占 4-8 GB 内存，--concurrent 别设太大（一般 16-64，看内存）。

⑤阶段 2 · Optimize（优化）

什么时候单独跑

  • 已经有 USD（外部来源，不是本工具转的）
  • 想用不同 preset 重新优化对比
  • 校验失败后，针对性修复

典型命令

# 非破坏式（推荐）：输出到新目录，保留原始
aif-pipeline optimize output_usd/ optimized/ \
  --preset so/generic/generic_preset.json

# 破坏式：原地改（不推荐，除非磁盘紧张）
aif-pipeline optimize output_usd/ \
  --preset so/generic/generic_preset.json

# 单文件优化
aif-pipeline optimize one_file.usd one_file_optimized.usd \
  --preset so/generic/generic_preset.json

选哪个 preset

preset用途路径
Generic通用 CAD 资产，不知道选哪个就选它so/generic/generic_preset.json
Vertiv 厂商Vertiv 电源设备（UPS/PDU）so/vertiv/
SPT 厂商SPT 设备（含 GB300 机柜）so/spt/
Trane 厂商Trane HVAC（空调）so/trane/
自定义用 Web UI 拖拽生成你保存的 JSON
generic_preset.json 做了什么（按顺序）：设单位/朝向 → 合并重复层级 → 清理网格 → 减面 → 算法线 → 清未绑定材质 → 去重几何 → 清空叶子 → 精简 primvar → 去重材质 → 修材质绑定 → 清小几何 → 算包围盒。12 步全套，不需要你操心顺序。

⑥阶段 3 · Validate（校验）

两条校验路径，选一条

路径命令需要 Kit?什么时候用
Kit 校验aif-pipeline validate是（要 GPU）本地开发、要 Scene Optimizer 加速版规则
OAV 校验uv run --directory oav validate否（CI 友好）无 GPU 环境、CI/CD、跑 AIF 专用规则

Kit 校验

# 标准：Basic + Usd + Omni 三类规则
aif-pipeline validate optimized/ validation/

# 加 metadata 前后的分阶段校验
aif-pipeline validate optimized/ validation_pre/ --stage pre
aif-pipeline validate optimized/ validation_post/ --stage post

# 针对 SimReady 特性校验
aif-pipeline validate optimized/ validation/ \
  --feature minimal_placeable_visual \
  --predicate IsError

# 自动修复（小心，会改文件）
aif-pipeline validate optimized/ validation/ --fix --output-assets fixed/

# 每条规则单独跑（诊断慢规则用）
aif-pipeline validate optimized/ validation/ --fine-grained

OAV 校验（无 Kit/GPU 也能跑）

# 跑所有 AIF 规则
uv run --directory oav validate --category AIF /path/to/asset.usd

# 只跑某条规则
uv run --directory oav validate --rule AIFMetadataChecker /path/to/asset.usd

# 只看错误（不显示警告）
uv run --directory oav validate --category AIF /path/to/asset.usd 2>&1 | findstr Error # Windows
注意：aif-pipeline run 命令的 validate 步骤用的是 OAV（不是 Kit 校验），所以 run 在 validate 这步不需要 Kit 启动。

⑦阶段 4 · Metadata（AIF 元数据）

给资产加属性，让仿真运行时知道"这是台 CDU，制冷量 200kW，重 800kg"。这是 SimReady 资产区别于普通 USD 的关键。

支持 4 种设备

类型设备属性数是否预填值
cdu冷却液分配单元81否，需手填
crah机房空调51否，需手填
ups不间断电源51否，需手填
gb300_rackNVIDIA DGX GB300 机柜28是（NVIDIA 默认值）

标准流程

# 1. 生成空白模板
aif-pipeline metadata create --type cdu --output cdu.json

# 2. 用编辑器打开 cdu.json，把 value 字段填上真实值
#    （manufacturer / modelNumber / 各种规格参数...）

# 3. 应用到 USD，生成 properties 子层
aif-pipeline metadata apply cdu.json \
  --output CDU_01_Properties.usda \
  --prim CDU_01

# 4. 把 properties.usda 作为 sublayer 组合进主资产 USD
#    （在 USD Composer 里做，或用 preset 的 add_layers 处理器）

# 5. 校验元数据是否齐全
uv run --directory oav validate --rule AIFMetadataChecker CDU_01.usd

更新已有元数据（不删旧值）

# 比对当前模板，补缺失的属性，自动检测设备类型
aif-pipeline metadata update CDU_01_Properties.usda

# 先看会改什么，不写盘
aif-pipeline metadata update CDU_01_Properties.usda --dry-run

电气时序（特殊路径）

# 把百万级 TIME,VALUE CSV 转成高效二进制 USDC
aif-pipeline metadata electrical phase1.csv phase1.usdc \
  --prim Root \
  --property Phase1_AC_Current

§常用工作流（复制粘贴）

工作流 A · 全流程一键跑（最常用） 
aif-pipeline run input_cad/ output/ \
  --spec scripts/data/creo_spec.json \
  --preset so/generic/generic_preset.json

跑 Convert + Optimize + OAV 校验。Metadata 之后手工补。

工作流 B · 只转 CAD（拿到原始 USD） 
aif-pipeline convert input_cad/ output_usd/ \
  --spec scripts/data/creo_spec.json \
  --concurrent 32 \
  --skip-existing
工作流 C · 只优化（USD 已经有了） 
aif-pipeline optimize input_usd/ optimized/ \
  --preset so/generic/generic_preset.json
工作流 D · 只校验（CI 友好，无 GPU） 
# 适合加进 CI/CD，机器不必有 GPU
uv run --directory oav validate --category AIF path/to/asset.usd
# 退出码 0 = 通过，非 0 = 有失败
工作流 E · 只加 metadata（设备资产交付前） 
aif-pipeline metadata create --type cdu --output cdu.json
# 编辑 cdu.json 填值
aif-pipeline metadata apply cdu.json --output CDU_01_Properties.usda --prim CDU_01
uv run --directory oav validate --rule AIFMetadataChecker CDU_01.usd
工作流 F · 多项目不同 Kit 配置 
# 项目 A 用 Kit 109，项目 B 用 Kit 110
cd ~/projects/project_a
aif-pipeline config add --project --from ~/build/ngc/USD_Composer_109.0.3
# 生成 ./aif-pipeline.yaml（项目级，优先级最高）

cd ~/projects/project_b
aif-pipeline config add --project --from ~/build/ngc/USD_Composer_110.0.0

进哪个项目目录就用哪个 Kit，互不干扰。

工作流 G · 大批量断点续跑 
# 第 1 次跑，跑了 500 个文件后机器挂了
aif-pipeline run input/ output/ --spec ... --preset ...

# 第 2 次接着跑（跳过已转的）
aif-pipeline run input/ output/ --spec ... --preset ... --skip-existing
工作流 H · 校验失败 → 自动修复 → 再校验 
# 1. 第一次校验，发现错误
aif-pipeline validate input/ report/

# 2. 让工具自动修复（输出到新目录，不动原始）
aif-pipeline validate input/ report/ --fix --output-assets fixed/

# 3. 重新校验修复后的
aif-pipeline validate fixed/ report2/

# 4. 如果自动修复不够，可能要改 preset 加针对性操作，
#    详见下方"读懂校验报告"

§怎么选 preset

决策树

你的资产是什么？
│
├─ 通用机械 / 不确定
│  └─→ so/generic/generic_preset.json  # 90% 场景选这个
│
├─ Vertiv 电源设备（UPS/PDU）
│  └─→ 看 so/vertiv/ 下面有没有对应型号
│
├─ SPT 设备或 GB300 机柜
│  └─→ 看 so/spt/（含 GB300 专用 preset）
│
├─ Trane HVAC
│  └─→ 看 so/trane/
│
└─ 上面都不匹配 / 想自定义
   └─→ 用 Web UI 拖一个出来

generic_preset.json 一定适合吗？

90% 情况适合。但有 2 种例外要调：

  • 不能减面（高精度仿真）→ 复制 generic_preset.json，删掉 decimateMeshes 那一步
  • 需要外部 payloads（GB300 这种大量重复结构的）→ 看 so/spt/gb300/gb300_payloads.json 的写法

§读懂校验报告

校验报告分 3 种严重性：

级别含义要不要管
Error严重不合规必须修，否则资产不合格
Warning建议修看情况，AIFMetadataChecker 缺属性只报 Warning
Failure规则自身没跑成环境问题（Kit 没装好 / USD 损坏）

常见报错 → 修复对应表

报错规则什么意思怎么修
UpAxisZupAxis 不是 Zpreset 加 editStageMetrics（upAxis=2）
AIFMetersPerUnit单位不对preset 加 editStageMetrics（metersPerUnit=1.0）
stage_has_default_prim没设 defaultPrimUSD Composer 里 Set as Default Prim
AIFRootIsXformableroot 不是 Xform结构问题，需要重构层级
AIFAssetAtOrigin资产不在原点调 transform，让 root 在 (0,0,0)
normals_valid / normals_exist没法线或法线坏preset 加 generateNormals（sharpnessAngle=60）
usdgeom_extent包围盒不对preset 最后一步加 computeExtents
geom_shall_be_mesh有非 Mesh 几何（如 Curves）需要重转 CAD，或手工转 Mesh
winding_order面绕序错preset 加 mesh cleanup 操作
AIFMetadataChecker（缺 common）缺 aif:core:* 属性跑 metadata create + apply 补全
AIFMetadataChecker（缺 spec）缺 aif:spec:* 设备属性对应设备模板，填具体规格值
AIFMetadataChecker（缺 sublayer）主 USD 没引用 properties.usda把 *_Properties.usda 加为 sublayer
修复闭环：报错 → 查上表 → 改 preset 或补 metadata → 重跑 optimize → 重跑 validate。不要改校验规则本身，那是规范。

§不想敲命令？用 Web UI

Asset Processor 是个浏览器界面，能做 CLI 能做的所有事，且可以拖拽构建 preset。

启动

# 在 repo root 跑（专用 terminal，会锁住）
uv run python asset_processor/server.py

# 浏览器打开
http://127.0.0.1:8080
停止服务：在跑 server 的 terminal 按 Ctrl+C。关浏览器不算停。忘了停下次启动会报 "Address already in use"，按 故障排查 杀进程。

Web UI 能做的

  • Preset Factory：拖拽组合 45+ Scene Optimizer 操作 → 配参数 → 保存 JSON
  • Convert / Optimize / Validate：填路径点按钮跑 CLI 同款命令
  • Metadata：管理设备模板
  • Config 管理：点 + Add 加 Kit 配置（等同 config add）

Web UI 不能做的

  • 批量上千文件（CLI 更适合）
  • 无人值守定时任务（用 CLI + cron/Task Scheduler）
  • CI 集成（用 OAV CLI）

§故障排查

报错 / 现象原因解决
command not found: aif-pipeline 没激活 venv，或没用 uv run 所有命令前加 uv run，或先 source .venv/bin/activate（Linux）/.\.venv\Scripts\Activate.ps1（Win）
Kit path not configured 没跑过 config add 见 配置 Kit 路径章节
WARNING Kit executable not found --from 传了 _build/ 而非 project root 用含 repo.bat/repo.sh 的目录
--spec required 没在命令行或 config 给 spec 加 --spec scripts/data/creo_spec.json，或 aif-pipeline config set conversion.spec "..."
转换/优化超时 装配太复杂或文件太大 --timeout 调大；降 --concurrent
Out of memory 并发太高，每进程 4-8 GB 降 --concurrent，16GB 内存建议 ≤ 2
批量部分失败 个别文件损坏或异常 重跑加 --skip-existing，只处理失败的
Address already in use :8080 Web UI server 没停 Linux: kill $(lsof -t -i:8080)；Win: netstat -ano \| findstr :8080 然后 taskkill /PID <pid> /F
OAV ImportError 依赖没装全 从 repo root 跑 uv sync
Web UI 加载 preset 报错 JSON 不是合法的 Scene Optimizer 格式 JSON 必须是"操作对象数组"，F12 看 console 错误
pythonScript 操作报错 AIF_PIPELINE_SAMPLES_ROOT 没设 重新跑 setup.sh/setup.ps1，或手工设环境变量
Windows UnauthorizedAccess PowerShell 执行策略限制 Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
Python 3.13+ 报错 部分依赖不支持 3.13 uv sync 会自动选 3.10–3.12，不用手工装

# 2. 单步：转 CAD

# 3. 单步：优化
aif-pipeline optimize IN OUT --preset so/generic/generic_preset.json

# 4. 单步：校验（有 Kit）
aif-pipeline validate IN OUT

# 5. 单步：校验（无 Kit，CI 友好）
uv run --directory oav validate --category AIF <asset.usd>

必要约定

  • 所有命令前 uv run 或先激活 .venv
  • 每次新开 terminal 要重激活 venv
  • convert/optimize/Kit-validate 必须有 Kit + RTX GPU
  • OAV 校验（无 Kit）可进 CI
  • 非破坏式输出（独立目录）优于原地改
  • --skip-existing 是断点续跑神器
  • metadata 必须作为 sublayer 组合进主 USD
  • 每跑完必校验，看到 PASSED 才算合格

§术语（使用者向）

术语大白话解释
USD3D 场景文件格式（.usd/.usda/.usdc）。Omniverse 的通用语言。
SimReadyNVIDIA 的"仿真就绪"标准。普通 USD 不一定能仿真，SimReady USD 可以。
AIFAI Factory。本工具针对的数据中心设备标准。
KitOmniverse 的引擎。USD Composer 就是基于 Kit 的应用。本工具的 convert/optimize 借 Kit 的能力干活。
USD Composer官方 Kit App，相当于 Omniverse 的"编辑器"。
Scene OptimizerKit 的优化扩展，本工具的 optimize 步就是调它。
preset优化操作序列的 JSON 文件，告诉工具"按这些步骤优化"。
spec 文件CAD 转换的配置 JSON，告诉工具"Creo/JT/DGN 怎么转"。
OAV离线版 USD 校验器，无 Kit 无 GPU 也能跑，CI 友好。
metadata资产的"身份证"属性（厂商、型号、规格等）。
aif:core:所有设备共用的属性（厂商、尺寸、重量等 15 个）。
aif:spec:设备专属属性（CDU 制冷量、UPS 功率等）。
CDU冷却液分配单元。
CRAH机房空调。
UPS不间断电源。
GB300NVIDIA DGX GB300 机柜，AI Factory 标准计算单元。
connection points标记设备开口（水管/电源/风道接口）的几何 prim。
primUSD 场景里的一个对象（一个 mesh、一个相机、一盏灯）。
sublayerUSD 文件叠加机制。metadata 写成单独 .usda，作为 sublayer 拼进主 USD。
uvPython 包管理器（替代 pip），本工具用它管依赖。

§下一步

交付一个 SimReady 资产的标准清单

来自官方 workflow-checklist，每个资产交付前都该过一遍：

  • CAD 成功转成 USD（pivot 在原点）
  • USD 校验通过（OAV 跑 --category AIF 全绿）
  • 用 generic_preset.json 跑过优化
  • 添加 AIF metadata（*_Properties.usda）
  • 添加 connection points（*_ConnectionPoints.usd）
  • 把 properties 和 connection points 作为 sublayer 拼进主 USD
  • 在 USD Composer 里目视检查无异常

交付物结构

<model_name>/
├── <model_name>.usd                          # 主资产（含 sublayer 引用）
├── layers/
│   ├── <model_name>_Properties.usda          # AIF 元数据
│   └── <model_name>_ConnectionPoints.usd     # 接口定义
├── payloads/                                  # 可选：外部几何
│   ├── internal.usd
│   └── external.usd
└── data/                                      # 可选：preset 备份
    └── <model_name>.json
停在这里？记住 3 件事：
  1. 4 阶段：Convert → Optimize → Validate → Metadata，可单跑可串跑。
  2. Kit 是命脉：config add 配错什么都跑不动。所有 GPU 操作走 Kit。
  3. OAV 是 CI 友好校验：无 GPU 也能跑，uv run --directory oav validate --category AIF。
